# 语义一致性审查（脚本之外的一层）

> 适用：叙事设定库、状态档案、多副本镜像文档 —— 任何「有校验脚本、但脚本只管结构不管语义」的套件。
> 结论先行：**`verify` PASS + 逐文件一致，只证明数据结构没坏，不证明内容自洽。**
> 实测：8 子档案 × 84 文件镜像全部一致的同一次，语义层仍查出 **14 处冲突**，其中 4 处会让下游（正文、结算、实现）直接写错。

## 0. 什么时候用

- 用户说「查一下设定有没有矛盾」「做个一致性检查」
- 文档经过多轮追加/补段/裁决之后（补段最容易与原素材打架）
- 校验脚本报 PASS 但读起来别扭、或同一件事在两处读起来不一样
- 要往库里加新机制/新规则之前（先清账再加）

## 1. 审查方法

**审查单位 = 同一概念的跨文件定义**，不是单文件通读。

推荐取证顺序：
1. 先跑机械层（校验 + 镜像一致性），把「结构问题」排除掉
2. 再对每个核心概念列「它被定义在哪几处」，逐个并排读
3. 对每个角色/实体，抽三类句子做「认人测试」：自称、称呼、口头禅 —— 冲突常出在这里
4. 特别审「后补的速览/摘要」：这类段落是后来凭印象写的，与素材冲突率最高
5. 特别审「当前状态」行：它是快照，最容易被后续事件甩在后面

## 2. 冲突类型表（S1–S12）

| 类 | 症状 | 处置 |
|----|------|------|
| **S1 后补段与素材相反** | 后补的「速览/摘要」写的自称、禁用词、默认值，与同文件正文和全库素材全相反（甚至与速览自己的例句相反） | **以素材为准改后补段**，留修订注写明原值 |
| **S2 层级/辈分写反** | 把下位写成「上位」 | 按权威排序表逐条核对称呼关系 |
| **S3 同一机制两套数值** | A 文件「3 点错乱/5 点崩坏」，B 文件「1 次掉点/2 次崩/3 次失效」 | 拆成**两条命名的轴**（累计轴／即时轴），各自阈值、互相引用、写明「独立计不替换」 |
| **S4 通用规则缺例外** | 通用规则写「一律 X」，实例档案长期「不 X」却没登记例外 | 档案侧新增「例外登记」小节 ＋ 规则侧加一句指向它 |
| **S5 同一事实两套构成** | 「A+B+C」里的 C，两处写法不同 | 权威行写死 ＋「以本行为准，另一处作废」 |
| **S6 同一事件两个日期** | 裁决日期与历史条目里的日期冲突 | 保留原文 ＋ 覆盖标注「此日只是补齐，原写在此属笔误」 |
| **S7 状态行滞后** | 「当前状态」停在三轮之前，结论碰巧还对 | 补成**一行完整时间线**（用 ｜ 串起每次转折） |
| **S8 待办仍列已完成** | backlog/钩子池挂着别处已写明「已发生」的事 | 移出 ＋ 表下留**修订注**（不静默删除） |
| **S9 重复档位** | 同一分级一处 3 档、一处 4 档（缺一档） | 保留完整版，另一处改**索引句**指向它 |
| **S10 简版/完整版无层级** | 同一机制两份写法并列，读者不知默认走哪个 | 标层级 ＋ 写「未指定时默认走完整版」 |
| **S11 同字段两处登记** | 索引行与正栏重复登记同一字段 | 一处加「另一处仅为索引，以本栏为准」 |
| **S12 措辞与自身规则冲突** | 「自 X 日起建档」vs「历史不追溯」规则 | 改「**统计**自 X 日起（更早按不追溯规则不计入）」 |

**优先级判据**
- **P0** = 会让下游照错写（正文/结算/实现）→ 必改
- **P1** = 数值/时间线失真 → 必改
- **P2** = 冗余、重复、噪音 → 建议改，可与 P1 同批

## 3. 修复流水线（顺序固定）

```
① 备份 + sha256sum（源文件 → 工作区外，附 SHA256SUMS.txt）
② 归档目录一律不动 —— 归档是无损原文；冲突在「权威侧」定义并注记「引用方作废 / 以本行为准」
③ 批量 patch：execute_code 里循环 (path, tag, old, new)，逐条打印 OK/FAIL
④ 每条改动带 📌 修订注（原值 + 为什么改 + 以谁为准）→ 防止下次有人照旧版改回去
⑤ verify → 正式同步 → verify-only → 用旧矛盾关键词全文扫残留（应为 0 命中）
⑥ 读回关键片段（含表格首尾）贴给用户，再报「修了几处 / 故意保留几处+理由 / 还欠什么」
```

要点：
- **不要改归档去"消除"矛盾**。归档的职责是留痕；矛盾要在权威侧定义，并写明引用方作废。
- **每条改动都要留修订注**，否则下一轮审计会把它当"笔误"改回去。
- 报告必须区分「已修」「故意保留（附理由）」「仍欠（需要用户裁决或下次结算）」。

## 4. 工具坑

| 现象 | 修法 |
|------|------|
| `patch` 对「CJK 标题行 + 下一行」锚点匹配失败（读回文本肉眼完全一致，工具仍报 Could not find a match 并把该段原样回显） | 该处改走 **Python 读全文 → 字符串插入 → `open(p,"w",encoding="utf-8",newline="")` 写回**；`newline=""` 防 LF→CRLF；写回后 `grep -c "<新增标记>"` 读回确认 |
| 同一文件多处改动 | `execute_code` 里 `edits=[(path,tag,old,new),...]` 循环 + 逐条打印，失败项汇总重试。实测一次 17 条零失败 |
| 改完结构变形（表格断行、相邻标题粘连） | 改后必读回**结构片段**（表格首行/末行 + 相邻标题），不只看目标行 |
| 归档维护脚本吃条目 / 备注条数超限 | 先跑归档脚本（保留最新 N 条），再跑校验，再同步；顺序颠倒会校验失败 |

## 5. 验收清单

- [ ] 机械层：校验脚本 PASS（WARN 逐条能解释）、镜像 N/N 一致、无 DRIFT
- [ ] 语义层：S1–S12 逐类过一遍，命中项都有落点
- [ ] 每条改动有修订注
- [ ] 旧矛盾关键词全库扫过，0 残留（除修订注自身）
- [ ] 归档未被改写
- [ ] 报告含「已修/保留/仍欠」三段
