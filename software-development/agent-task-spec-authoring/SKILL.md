# Agent 任务书编写工作流

把项目文档（需求/功能设计/角色分工/契约）汇总成一份**给 AI Agent 直接读取执行**的任务书。核心价值：agent 打开一份文件就拿到全部任务上下文，不用翻十几个文档；同时把"待确认的契约差异"提前暴露，避免返工。

## 触发条件

- 用户要求"整理成方便给 agent 读取执行的文档" / "给 agent 写任务书" / "明确约束和边界"
- 用户要把某个开发域/角色分给 AI agent（或人类队友）并希望边界清晰
- 项目交接、新人/新 agent 上手准备

## 核心原则

1. **以最新文档为准**：分工矩阵/README/AGENTS.md 可能已更新，用户自己的认知可能滞后（本次会话：用户以为负责"风控+操作"，最新文档已把操作线分给他人——先读文档再信用户的自我描述，发现差异直接指出）
2. **交叉验证三处**：分工矩阵（DRI 表）↔ 代码文件头维护人 ↔ 代码实际命名。三者不一致=待确认事项（本次发现：DRI 矩阵写张树灿，代码文件头全写胡浩；文档写 `AgentBase`，代码用 `BaseAgent`）
3. **不动代码**：侦察阶段只读（find / wc -l / read_file），明确告知用户"未改动任何文件"
4. **契约差异列清单**：需求文档示例值 vs 正式规则文档 vs 功能设计的阈值/编号不一致时，统一列出"待确认事项"表格，让用户明早/会上拍板
5. **文件放 agent 能读到的地方**：代码仓库根目录（如 `RISK-DOMAIN-TASK.md`），文件名用 ASCII，内容用中文；喂 agent 时给出标准开场白

## 工作流

### 第 1 步：侦察（只读）
- `find . -maxdepth 2 -not -path './.git/*'` 看目录结构
- 列 docs 全部文件 + 关键文件大小，确定读取优先级
- 识别权威源顺序：`AGENTS.md` > 角色页 > `docs/01-architecture/*`（冻结契约）> `docs/_ref/*`（原始需求）

### 第 2 步：读关键文档（批量并行 read_file）
- README / AGENTS.md / 文档主索引（总览 + 全局铁律）
- 用户角色页 + 职责总览矩阵（DRI 边界）
- 冻结契约：接口契约、事件总线、Tool 清单、DDL、故障治理（至少契约/事件/Tool 三份）

### 第 3 步：交叉验证（产出待确认清单）
- 分工矩阵 ↔ 文件头维护人 ↔ 用户自我认知
- 文档命名 ↔ 代码命名（import 什么基类）
- 需求示例阈值 ↔ 正式规则文档阈值（如需求"7天≥10次" vs 规则文档"7天≥20笔且≥10万"）
- 等级/状态映射（规则 4 档 vs 表 3 档）

### 第 4 步：提炼原子任务
- 每个 Agent/域拆成 4-6 个原子任务表格：`# | 任务 | Done 条件`
- 附核心规则/意图/权限等"核心资产"完整表格（agent 一次拿到全部参数，不必再翻源文件）

### 第 5 步：成稿（6 要素 + 2 附录，见 templates/task-spec-template.md）
1. 负责内容（DRI 写权限/只读/协作方）
2. 任务需求（原子任务 + 分级/流程铁律 + API 清单）
3. 所需技术栈（版本锁死 + 依赖 + 关键约束）
4. 代码做法（文件现状→要实现什么 + 实现要点编号 + 测试要求）
5. 接入骨架（4 抽象方法代码示意）
6. 边界和红线（不许越界 + 违反=返工）
7. 验收标准（Done 条件勾选清单）
8. 参考文档索引 + **待确认事项**（⚠️ 明早冻结会提问清单）

### 第 6 步：交付
- 告知文件路径、结构表、待确认清单
- 给标准喂 agent 开场白：`读取 <任务书文件>，按任务书实现 XX 域。先读 AGENTS.md 和引用的契约，只写你域的文件，禁止越界。`
- 用户澄清分工后（如"我和 X 共同负责"），重写任务书覆盖整个域，保留文件所有权矩阵避免并发冲突

## 坑与注意

- **分工可能已细化**：启动会文档 → 可执行文档会调整人员归属，不要沿用用户上一版认知
- **占位文件陷阱**：骨架里已有 TODO 占位文件（`maintenance: 某人` 可能是模板复制），不代表实现完成，也不代表 DRI
- **文件头维护人 ≠ DRI 矩阵**：模板批量生成时维护人会串，列入待确认而非自行判断
- **用户说"共同负责"时**：任务书覆盖整个域（两条线任务全写上），但文件所有权仍按矩阵拆分（避免两人改同一文件），在开头注明执行模式
- **HTML 需求文档**：先转纯文本再读，方法见 references/html-text-extraction.md
- **不要越界写文档**：`docs/` 目录通常有 DRI（如朱瑶维护架构文档），任务书放仓库根目录即可

## 支持文件

- `templates/task-spec-template.md` — 任务书 6 要素模板
- `references/html-text-extraction.md` — 本地 HTML 文档转纯文本方法（python 正则）
