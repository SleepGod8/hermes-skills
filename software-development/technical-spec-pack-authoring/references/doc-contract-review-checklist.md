# 跨文档契约一致性审查清单

来源：AI 数字化人才平台 8 轮交叉审查实战沉淀（2026-08，主人+鲸鱼女孩审查视角）。
用途：生成全套技术文档包后 / 每轮修复后逐项自查；审查输出按严重度排序（P0 硬伤 / P1 风险 / 毛毛刺），修复后 grep 旧术语 0 残留。

## P0 硬伤类（必须修，否则开发位按旧版实现必踩坑）

1. **定义冲突**：同一概念（结局标签 / 状态 / 角色 / 令牌 / 枚举）在多个文档写法不同。
   - 案例：需求权威源结局标签 4 值（含 churned），下游 3 值漏 churned → 以需求权威源为准补齐下游。
   - 案例：Offer 状态机 `accepted | declined → withdrawn` 歧义 → 改显式分支。
2. **有表无 API（缺口）**：数据库设计了表但 API 文档无对应接口，结局标签/状态机无驱动入口。
   - 案例：offer_orders 有表无 API → 补 Offer CRUD + onboard + churn + withdraw。
3. **状态转换无驱动接口**：转换表允许的转换没有业务接口触发。
   - 案例：任意阶段 withdrawn 无接口 → 补 `POST /candidates/{id}/withdraw` 通用退出入口（有 offer 时强制走 offer 接口）。
4. **编号悬空**：文档引用 FR-x.y / TC-x-y 但源文档没有。
   - 案例：API 引用 FR-3.9，需求表止于 FR-3.8 → 补 FR-3.9 或改引用。
5. **令牌/认证方案定义冲突**：多个令牌名并存（initial_token / candidate_token / access_token / Bearer / 一次性/可复用两种模式）。
   - 处置：收敛为两阶段（一次性 exchange_token 兑换短期可复用 candidate_jwt，绑定 scope，面试提交后失效），旧术语全量 grep 清零（含测试用例、FR 描述、ADR）。

## P1 风险类（不立即炸但会拖累验收/安全）

1. **请求参数信任客户端**：user_role / permission_scope 由客户端传 → 角色一律从 JWT 解析，scope 服务端校验（值 ∈ 白名单 + 调用者有权授予），禁止信任请求参数。
2. **写接口无角色约束**：上传/创建/状态变更接口未标角色 → 显式 require_role，补越权测试用例。
3. **会话无归属校验**：thread_id 只凭 id 查询可跨用户读取 → 会话记录绑定 user_id/company_id/permission_scope，查询/续聊时校验归属。
4. **事件写入无约束**：event_type 是普通字符串可写任意值 → Pydantic Enum + 状态转换表（单一权威源 core/events.py）+ 数据库唯一索引防重。
5. **事务一致性缺失**：事件、业务状态、候选人主状态分步写可能部分成功 → 同一数据库事务 + idempotency_key + (candidate_id, idempotency_key) 唯一索引，任一步失败整体回滚。
6. **向量维度未冻结**：1536 / bge-m3 / text-embedding-3 并存 → 冻结一个模型+维度，换模型走显式迁移流程（配置+重建集合+更新文档+验收证据）。
7. **密钥方案缺失**：PII 加密无密钥托管/轮换/备份 → 环境变量 + 双 key 轮换（ACTIVE/PREV）+ 备份与恢复演练。
8. **验收指标不可执行**：'准确率≥99%' '杜绝幻觉' '无人值守' → 配测试集+统计口径；无人值守说明人工节点由测试代理/固定表单代替。

## 毛毛刺类（观感，但建议顺手清）

1. 章节编号跳号（4.4.x 应为 3.4.x）。
2. 拼写错误（onbaorded → onboarded）。
3. 测试用例编号顺序乱（N-03 在 N-01 前）。
4. 里程碑表漏新阶段（如前端 MS4.5）→ 同步到概要设计的里程碑关系表。
5. 前端页面映射表漏新接口（onboard/withdraw）。
6. 证据目录漏新测试文件。
7. 旧框架/角色措辞残留（Dify 一期 vs 二期、Vue3/React 未定案）。
8. 文档引用了不存在的 DRI 兜底链 → 统一为一处权威表述，其余引用之。

## 审查执行要点

- 每轮审查后：修复 → grep 旧术语 0 残留 → 确认新术语跨文档一致（API/状态机/测试/映射/DB 五处）。
- 涉及用户决策（保留/删除概念、范围定案）时给出**推荐默认值 + 理由**，让用户只需确认/否决（如 churned 保留：归因分析需要入职后流失）。
- 新增接口同步五处：API 文档 + 状态机 + 测试用例 + 前端映射表 + 数据库表注释/字段。
- 答辩/面试项目：评测集构建要显式排进里程碑（MS1.5），证据目录规划即标注"尚未创建，按里程碑落地，不得虚构"。
