# 跨文档一致性审计清单（doc suite 交叉分析）

按严重度排序。用途：① 文档生成后自查；② 评审他人文档时快速定位硬伤。
实践验证来源：AI 招聘平台文档体系两轮交叉分析（2026-08，A-F + 4 项残余问题）。

## A. 硬伤（必改）

1. **定义冲突**：同一概念/值集在不同文档不一致
   - 典型：结局标签 3 值（onboarded/rejected/withdrawn）vs 4 值（+churned）
   - 检查：对关键值（事件类型、结局标签、状态机、权限角色）全局 grep，确认覆盖全部文档且值一致
   - 修复：以需求权威源（REQUIREMENTS.md）为基准统一，下游文档全部对齐

2. **编号悬空**：文档引用了不存在的 FR/TC/章节编号
   - 典型：API 文档引用 FR-3.9，但需求文档只到 FR-3.8
   - 检查：提取全部引用编号 vs 定义全集，diff 找出悬空
   - 修复：补需求条目（优先）或改引用

3. **契约无驱动入口**：表/事件设计了，但没有产生它的 API
   - 典型：offer_orders 表 + offer_sent 事件都存在，却无 Offer API → 结局标签状态机永远无法流转
   - 检查：每个"状态机/结局标签"必须能追到具体接口
   - 修复：补 API（含请求/响应示例）+ 测试用例

## B. 缺口（需补）

4. **身份/账号体系缺失**：流程需要登录/令牌但无接口契约
   - 典型：候选人要"登录答题"，但只有 HR login，无候选人创建/令牌发放
   - 修复：补候选人创建 API + 一次性答题令牌（Bearer、scope 绑定、防重放），详细设计补令牌实现

5. **前端/展示范围模糊**：页面映射存在但一期范围未定
   - 修复：决策落到 ADR（如"一期 Vue3 最小页面集"），且技术栈表/里程碑/开发指南同步改，grep 旧表述确认 0 残留

## C. 小瑕疵

6. **章节跳号**：模块 4 写成 4.4.x、模块 5 写成 5.5.x（应为 3.4.x/3.5.x）
   - 检查：章节号与顶层章节一致

7. **概念混用**：示例字段值类型错误
   - 典型：`outcome_label: "offer_sent"`（把事件类型写进结局标签字段）
   - 修复：示例值必须取自该字段的合法值集，并附一行概念说明

8. **口径漂移**：同一技术在不同文档表述不一
   - 典型：Dify 需求文档写"一期"，ADR-2 却定"一期直连、二期接入"
   - 修复：以 ADR 为唯一口径，需求技术栈表加注"口径（与 ADR-x 一致）"

9. **用例编号悬空**：N-02 存在但 N-01 缺失
   - 修复：补用例或重排，编号必须连续

## D. 隐藏工作量

10. **评测集/合成数据未排期**：100 份简历/50 组标注/50 问答/20 面试抽样，本身是大工程
    - 修复：里程碑显式加 MS1.5 之类，指定 DRI（验收位主责）、先于被测模块完成，避免开发位"没评测集就不自测"

## 修复规范

1. 按严重度排序逐项处理，每项先给明确裁决（保留/补/改/删）再动手
2. 修完做回归验证：grep 旧值/跳号/悬空引用，确认 0 残留
3. 冻结契约变更要同步所有引用文档 + 测试用例 + 版本记录
4. 有决策的项（如 churned 是否保留）先定裁决再改文档，裁决理由写进文档（答辩可引用）
