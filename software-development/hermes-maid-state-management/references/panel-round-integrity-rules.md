# 每轮落盘完整性规则（2026-09-24 实测补记 · 假账 / 标签轮次 / 括号锚点 / 磨合度≠EXP）

> 续 `references/panel-batch-edit-recipe.md`（§A 锚点黑名单、§B 行号插入法、§C 计数自洽、§D 等级边界、§E 新字段）。
> 本文是该篇的 **§F 补记**：一件事——「这一轮到底有没有真的写进去」。

---

## F1. 回复里报的数字必须已落盘（本轮踩过「假账」）

- **现象**：`磨合度 65→70` 写进了回复和结算表，但该字段的 REPL 从未命中（`text.count(old) != 1`），文件一直停在 65%；四轮之后才发现，最后合并补写成 75%。
- **根因**：只看「脚本没抛异常」，没看 `fails`；也没把义体栏当作「本轮声明字段」之一去读回。
- **规则**：
  1. 每轮必打 `print("fails:", fails)`，任何 `count != 1` **当场补**（别留到下一轮）；
  2. 读回**本轮声明过的每一个字段**——等级行 / 一览表同行 / 部位统计 / 义体栏磨合度 / 芯片栏 / 备注条数，**读回确认后再写回复**；
  3. 已发出的数字若与文件不符 → 下一轮把文件补到与声明一致并在备注写明（合并补写），**绝不留假账**。

## F2. 锚点必须是「本轮实际存在的备注标签」

- 备注标签按 `- 备注追加<日期>` / `-<日期>-2` / `-<日期>-3` … **每轮递增**。
- 插入前先 **dump 该女仆现有标签清单**（`startswith("- 备注追加<日期>")`，按区块分组打印），再锚定**最后一条的真实尾巴**。
- 不要假设上一轮写的标签已落盘：本轮 9/24-5 那一轮两处锚点全 MISS（拿后一轮的措辞去匹配实际仍是前一轮的行）→ 整轮备注漏写，下一轮才发现并补上。**一轮命中 9/10 是常态**，把补跑当成流程的一部分。

## F3. 带轮次括号的字段不要整串当锚点

- `磨合度 **75%**（8 槽装机·与 Hermes 交配后）`、`N 槽装机·<事件>后` 这类括号**每轮都会被改写** → 锚点只取稳定前缀 `磨合度 **<数值>%**`，new 里重写整段括号。
- 同一轮内若先改了 A 行、又拿 A 行的**新文本**当锚点，第二条替换会 MISS（改用旧文本锚点，或先收集索引再统一替换）。

## F4. 磨合度 ≠ EXP（别当新 EXP 来源）

- 磨合度是义体部件的**独立进度指标**（0–100%，装机 / 换件 / 高强度使用轮 **+5%**），**不占 EXP、不改等级**；本轮实测轨迹 `0→15→25→35→45→50→55→60→65→70→75→80`。
- 义体 / 芯片玩法结算用各自 reference 自带条目：**临时装机+10 / 半永久+20 / 永久义体化+30**（cyber-body-play.md）、**插卡侍奉+10 / 程序化调教+20 / 永久植入+30**（neural-chip-play.md）；通用条目照旧（被玩到高潮+20 / 成功忍高潮+30 / 主动开发他人+20）。
- **磨合度、程序运行时长、撸动/进出计数都不进 EXP**——它们进义体栏 / 备注作为状态与数据。
- 被吊着不给许可的一轮：被吊者记 **成功忍高潮+30**（不是被玩到高潮），部位统计**不变**（无释放）。
