# 飞书文档登录技术细节

> **⚠️ 强烈建议**：优先让用户自己在浏览器中登录，然后把文档链接发给你。以下技术细节仅供无法绕开登录时的参考。

## 飞书登录弹窗行为

- 点击页面右上角"登录/注册"按钮后弹出登录弹窗（overlay/modal）
- 登录弹窗使用 **React portal 或类似框架**渲染，元素不在常规 DOM 树中
- 访问性树（accessibility tree）只能捕获到部分元素，ref ID 在每次页面重载后变化

## 可识别的元素

通过 `browser_vision(annotate=true)` 可以定位到以下元素（ref 每次不同，需重新获取）：

| 元素 | 标识 | 操作方式 |
|------|------|---------|
| 手机号输入框 | placeholder="请输入你的手机号" | `browser_type(ref="eXX", text="手机号")` |
| 验证码输入框 | placeholder="请输入验证码" | `browser_type(ref="eXX", text="验证码")` |
| 获取验证码按钮 | 视觉可见，但 DOM 不可直接定位 | 见下方说明 |
| 同意协议复选框 | "我已阅读并同意..." | `browser_click(ref="eXX")` |
| 登录/注册按钮 | button text="登录/注册" | `browser_click(ref="eXX")` |

## 获取验证码按钮的解决方案

该按钮不在 DOM 的 button 元素列表中，需要通过 JavaScript 间接定位：

```javascript
// 方法一：通过 class 属性模糊匹配（成功率最高）
document.querySelector('[class*="verify"]').click()

// 方法二：遍历所有元素按文本匹配（不推荐，性能差）
// 建议优先使用方法一
```

## 常见坑

1. **弹窗自动关闭**：点击"获取验证码"后，如果 browser 标签页失去焦点或页面发生导航，弹窗可能自动关闭，需要重新点击"登录/注册"按钮
2. **验证码输入框 ref 变化**：每次弹窗关闭后重新打开，所有 ref ID 都会改变
3. **无法判断短信是否发出**：点击按钮后无法从 DOM 判断短信是否成功发送，需依赖用户反馈
4. **多次尝试易触发风控**：多次获取验证码可能触发飞书的风控机制
