# Technical Tutorial Authoring (技术教程编写)

## Overview

当用户要求"把XX内容整理成教程/MD文件"、"根据网页+自己补充写一份XX教程"时，使用此技能。
核心流程：浏览器提取受限网页内容 → 结合自身知识补充 → 结构化输出 MD 文件。

## When to Use

- 用户提供网页链接，要求提取内容并整理成教程
- 用户要求"把XX知识写成markdown教程"
- 需要从飞书/语雀/Notion等受限文档页面提取信息后补充完整
- 用户在学习某技术（如Docker、Git、MySQL），需要系统化的学习文档
- **用户连续分享多张截图/图片**，要求整合成结构化文档或思维导图
- 用户要求输出**XMind 兼容格式**的 Markdown 文件
- **注意**：本技能负责内容整理和文档编写，不负责代码审查或项目分析

## 工作流程

### Step 0 (Screenshot/Image Source): 处理多张截图内容

当用户连续发送多张截图（vision_analyze），要求整合为文档时：

1. **逐张解读**：对每张截图用 `vision_analyze` 提取内容，记录关键信息
2. **识别课程脉络**：多张截图通常是同一课程/文档的连续页面，根据内容推断章节顺序
3. **按目录大纲归类**：如果用户提供了目录/大纲，就按它组织；否则自行归纳章节结构
4. **去重合并**：同一概念在不同截图中重复出现的，合并到一处
5. **补充缺失环节**：截图间可能有跳跃，用自己的知识补充中间环节
6. **关联用户实践**：把理论内容和用户已有的实际操作联系起来（比如"你在第X步已经做过了"）
7. **导出为 XMind 兼容 Markdown**：按下方 XMind 格式规范输出

### Step 1: 提取网页内容
使用 `browser_navigate` 访问链接，然后：
- 通过 `browser_snapshot(full=true)` 获取页面文字内容
- 点击目录中的各个章节，逐一提取内容
- 注意页面可能的**登录遮罩**——未登录状态下只能读取部分内容，记下能读到的内容
- **如果用户已在 Hermes Studio 内置浏览器打开文档**（已登录/有权限，如飞书），优先用 `hermes_studio_browser_toolset` 读取当前标签页，流程和坑见 [references/hermes-studio-browser-reading.md](references/hermes-studio-browser-reading.md)

### Step 2: 整理网页原始信息
将提取到的文字归纳：
- 列出文档的**目录结构**（各章节标题）
- 记录每个章节的**关键语句**（原文要点）
- 标注哪些是**图片被挡**或**内容不可见**的部分

### Step 3: 结合自身知识补充
对于网页中缺失/不完整的内容，用自己的知识补充：
- 常见命令的完整表格（命令+说明+示例）
- 核心概念的类比解释（如"容器=集装箱"）
- 实用技巧和注意事项（如数据卷挂载的坑）
- 速查表/附录（方便日后翻阅）

### Step 4: 输出结构化 MD 文件
文件结构模板：

```markdown
# XX 教程

## 目录
1. [XXX](#1-xxx)

## 1. XXX
### 1.1 概念
### 1.2 用法

## 常见命令
| 命令 | 说明 | 示例 |
|------|------|------|

## 附录：速查表
```

### Step 5: 保存到桌面或用户指定位置
使用 `write_file` 写入文件，路径优先选 `~/Desktop/` 或用户指定路径。

### Step 6 (Bonus): 处理"怎么打开/导入/转换"的后续问题
用户可能会在教程写完后问"XMind能不能导入md"、"怎么转成思维导图"等问题。需要：
- 提供**格式兼容性**信息（如 XMind 对 Markdown 的导入限制）
- 推荐**替代方案**（如 markmap.js 在线转换、FreeMind 格式等）
- 主动询问是否需要帮忙转换格式

## XMind 兼容 Markdown 格式规范

当用户要求输出"方便导入 XMind"的 Markdown 文件时，遵循以下规则：

### 标题层级 → 思维导图层级

| Markdown 标题 | XMind 层级 | 说明 |
|---------------|-----------|------|
| `# 标题` | 中心主题（Central Topic） | 整个文档的主题 |
| `## 标题` | 主要分支（Main Topic） | 章节标题 |
| `### 标题` | 子分支（Subtopic） | 小节标题 |
| `#### 标题` | 叶子节点（Floating Topic） | 子小节/概念名 |
| `- 列表项` | 详细内容（备注或子节点） | 具体说明 |

### 关键规则
- **只用标题层级和列表**：XMind 导入 MD 时只识别 `#` 标题和 `-` 列表，不识别表格/代码块为思维导图节点
- **代码块保持原样**：代码块在 XMind 中显示为文本内容，附在父节点下
- **列表项缩进**：用 `-` 列表表示同级多项内容，用缩进表示层级关系
- **表格插入正文**：表格放在对应的标题/列表下方，作为补充说明
- **总层级不超过 5 级**：XMind 超过 5 层会显得杂乱

### 推荐结构模板

```markdown
# 课程名称（中心主题）

## 第一章（主要分支）
### 1.1 概念（子分支）
- 定义
- 特点
### 1.2 用法（子分支）
- 方式一
- 方式二

#### 代码示例（叶子节点）
```python
print("hello")
```

## 第二章（主要分支）
### 2.1 ...
```

### 验证方法
- 文件保存后，用户可以拖入 XMind（文件 → 导入 → Markdown）
- 或者用在线工具 https://markmap.js.org/ 即时渲染验证层级结构
  
## 用户偏好
- 用户偏好**表格对比**（如绑定挂载 vs 命名卷的对比表）
- 用户偏好**类比/人话解释**（如"容器就是集装箱"）
- 用户偏好**分点说明**，而不是大段文字
- 教程尾部附**速查表**方便日后翻阅

## Common Pitfalls

1. **飞书文档登录遮挡**：未登录状态下图片无法访问，不要硬等——直接用自身知识补充。飞书会显示"登录/注册"按钮，文字内容仍可部分提取（目录、标题、关键语句），图片会被完全遮挡。
2. **不要尝试帮用户登录**：绝不要尝试用用户的账号密码登录任何第三方网站。安全风险太高，且 Hermes 的 browser 工具对飞书登录弹窗支持极差——登录弹窗使用 overlay/portal 渲染，元素不在标准 DOM 树中，ref 在每轮交互后变化，验证码按钮只能通过 `document.querySelector('[class*="verify"]')` 间接找到，且短信发送后弹窗经常自动关闭导致中断。如果用户坚持要登录，建议直接让用户自己操作。参考 [references/feishu-login-techniques.md](references/feishu-login-techniques.md) 了解具体技术细节。
3. **页面中图片被遮罩挡住**：飞书/语雀等文档的图片在未登录时被遮罩完全遮挡。如果图片包含关键信息（如命令截图、架构图），用自己的知识补充完整内容，并标注"已用自身知识补充"。
4. **页面 ref 失效**：页面导航后 ref 可能改变，需要重新 `browser_navigate` 获取新 ref
5. **内容太冗长**：单篇 MD 控制在 15-20KB 以内，过长的内容拆到 `references/` 子文件中
6. **遗漏实操命令**：教程必须附带可以直接运行的命令示例，不能只有概念描述
7. **忽略版本差异**：Docker 等工具版本可能变化，标注版本信息（如 `mysql:8.0`）
8. **截图内容不完整**：用户发的截图可能只截了部分内容（如只截到代码一半、表格被截断等），需要用上下文推断完整内容，并标注"截图截断，已补充完整"
9. **多截图顺序错乱**：用户可能不是按顺序发截图的（先发中间页，再发前面页）。根据内容推断正确顺序，必要时在文档中标注"根据内容推测章节顺序"
10. **XMind 导入后代码块格式异常**：XMind 对代码块的渲染可能丢失缩进或语法高亮。建议代码块前后加空行，内部不要用制表符
11. **Hermes Studio 内置浏览器 MCP 工具**：`hermes_studio_browser_toolset` 调用必须给 `action` 参数（list/describe/call），tabs 空参数会报 "Invalid browser tab action"；`read_text` 对 RootWebArea/Iframe 返回空文本，需读具体 StaticText 节点或直接用 snapshot 的 text 字段；长文档要循环 scroll+snapshot 直到内容不再变化。详见 [references/hermes-studio-browser-reading.md](references/hermes-studio-browser-reading.md)

## Verification Checklist

- [ ] 网页内容已全部提取并整理
- [ ] 缺失部分已用自身知识合理补充
- [ ] 有表格对比关键概念
- [ ] 每个命令都可直接复制运行
- [ ] 有速查表或附录
- [ ] 文件保存到用户期望的路径
- [ ] 文件编码为 UTF-8，中文显示正常
- [ ] （如要求 XMind 兼容）标题层级是否克制在 5 级以内，是否只用 `#` 和 `-`
- [ ] （多截图来源）截图遗漏的章节是否已用自己的知识补充完整
