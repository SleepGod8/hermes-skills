# 校验器报错分诊：格式 → 口径 → 真数值错（2026-10-28 实战）

> 配套：`references/state-archive-writeback-sop.md`（落档序列 / 表格插行锚点 / patch 返回值检查）。
> 场景：状态档案校验器（如 `verify_panels.py`）报 WARN/FAIL 时，**先分诊再动手**，否则会白改一遍数据。

## 一、三类报错，处理顺序不能反

| 类 | 典型输出 | 根因 | 处置 |
|----|---------|------|------|
| **① 格式** | `⚠️ [C6] 部位统计格式异常：['秘处: **18**/0', …]` | 值单元格里混进了 Markdown 强调 / 全角符号 / 多余空格 | 去掉标记，数值原样保留 |
| **② 口径** | 数值明明对却报不一致 | 解析器取错了位置（括号里的溯源说明被当主值、两张表共用列结构互相覆盖） | 调解析口径，不改数据 |
| **③ 真数值错** | 与前值/总览/历史对不上 | 漏记前一轮、从 0 起算、升级未清零 | 改数据，并在备注写明修正依据 |

**实战案例（本次踩的是①，一度以为是③）**：

```
❌ ｜ 秘处: **18**/0 ｜ 后庭: **12**/0 ｜ 男根: 0/**76** ｜ 全身: **24**/0
✅ ｜ 秘处: 18/0 ｜ 后庭: 12/0 ｜ 男根: 0/76 ｜ 全身: 24/0
```

加粗只是为了「标出这次涨了」，结果校验器按纯文本解析单元格 → 报「格式异常」。
把它当数值错去改数，就会把正确的数字改错。**去掉标记后立刻 PASS。**

规则：

- 数值行 / 统计行只用**纯文本数字**
- 「这次涨了」的留痕写进**备注**（自由文本，随便加粗）
- 报「格式异常」时，先自问：**我是不是在值里加了标记？**

## 二、修完格式必须重跑两步

```
修改 → verify（应 PASS） → sync
```

因为第一次 sync 已经把「带标记的版本」镜像到子档案了。只改源不重跑 sync，副本与源立刻分叉；而 `DRIFT` 检测又只针对「副本被本地改过」，不会替你抓这种「源改了没同步」。

## 三、WARN 与 FAIL 的读法

- **FAIL**：决定返回码，必须清零。
- **WARN**：可能是已登记的规则例外（见 `mirrored-state-governance` 的 `rule-exceptions.md`），也可能是真问题。**每个 WARN 都要能一句话解释**；解释不了就是没查清。
- 汇报时把 WARN 单列出来，不要藏在「PASS」后面——结论 PASS 但带 2 个 WARN 时，只说 PASS 等于瞒报。
