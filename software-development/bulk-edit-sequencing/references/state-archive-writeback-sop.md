# 状态档案「增量落档」SOP 与坑（2026-10-28 实战）

> 场景：多副本状态档案已经治理完，进入长期使用期——每次互动/任务结束都要往同一批文件追加数据。
> 本文件只补 SKILL.md 之外**实测踩到的落档细节**；重构/拆分/校验器设计见 `mirrored-state-governance`。

## 一、标准序列（顺序是硬要求）

```bash
# 1) 先改数据（三处一起，顺序：实体 → 总览/索引 → 故事/日志）
#    a. entities|maids/<实体>.md  —— 数值 / 装备 / 部位统计 / 追加一条备注
#    b. <overview>.md             —— 快速一览表对应行（字段真的变了才改）
#    c. story-log.md              —— 主线一行 + 该实体「上次到哪／欠什么／下次钩子」
# 2) 备注超上限时归档（幂等）
python scripts/<maintain>.py --apply
# 3) 校验（FAIL=0；WARN 必须能解释）
python scripts/<verify>.py
# 4) 校验过了，最后才镜像同步
python scripts/<sync>.py
```

**verify 必须在 sync 之前**：先同步再发现数据有问题 → 修完还得再同步一次，等于双写 + 多一个备份目录 + 两份「基线」看着像分叉。

其他三条：

- 维护脚本幂等，「0 条搬运」是正常输出，可放心重试。
- 总览/索引表**只在该字段真的变了时**改（等级/EXP/装备/印记）。细账（部位统计、库存量、连击次数）不在总览里，别硬塞进去凑热闹。
- 非权威会话（子档案）只输出「结算报告」，落盘统一回唯一写入者做。

## 二、值单元格里不要放 Markdown 强调

```
❌ ｜ 秘处: **18**/0 ｜ 男根: 0/**76**
✅ ｜ 秘处: 18/0 ｜ 男根: 0/76
```

格式检查（如 `verify_panels.py` 的 C6）按**纯文本**解析数值单元格，加粗会报「格式异常」。它报的是**格式**，不是**数值错**——极易被误读成「数据写错了」而白改一遍。

规则：**数值行纯文本；要留痕「这次涨了」写进备注**（备注是自由文本，随便加粗）。

## 三、Markdown 表格插行：锚点选择

- **不要用分隔行当锚**：`|---|---|---|` 与实际 `|------|---------|------|` 长度不同 → 失配，`patch` 返回 `success: False`，看着像工具坏了。
- **用第一条数据行的固定前缀当锚**（如 `| 9/23 | **实体首秀**`），把新行插在它前面。
- 同一文件里多张表共用列结构时，锚必须带上该表的独有文字，否则会插错表。
- 插完检查表头「最新 = X 日」这类时间戳说明是否要一起改。

## 四、批量改动必须逐条检查 `success`

`hermes_tools.patch(path, old, new)` 返回 **dict**，失败时**不抛异常**：

```python
r = patch(p, old, new)
print(f"{p}: {r.get('success')} {r.get('error','')}")
```

只看 diff 不检查 `success`，就会「以为改了其实没改」，通常要等校验器或读者发现少条目才暴露。

## 五、条目与数值口径

- **合并粒度**：同一批连续几场（破功→口交→结算）写**一条**备注，内部 ①②③ 分节；事故、裁决、改设定**单独立条**备查。
- **跨场连记**：累计量的开场值 = 上一轮落档的结尾值，禁止从 0 起算；结算写清推导 `实测 X（存 Y＋溢出 Z）`，三数对不上说明前一轮漏记，回头补而不是硬写。
- **清零/释放类事件**：按日期列，不编号（「第 N 次」的口径会在多次追加后漂移）。
- **跨日条目**写日期区间或拆条；日期口径以条目内首个日期为准。
