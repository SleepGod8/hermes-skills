# 对齐提案决策表模板（"建议默认值 + 不采纳后果"格式）

> 来源：智能财富管家项目（Day 0 → Day 1 冻结会）实测有效。
> 要点：决策者不需要从零想方案，只需对每项说"同意"或改默认值。15 项 3 分钟读完。

## 单事项结构（提案正文）

```
#### A1. <事项名> —— 🔴 最高优先
- **现状**：<一句话，附证据/文件>
- **影响**：<不处理的后果，量化到验收项>
- **建议**：<方案 a/b/c 或具体字段清单>
- **决策点**：<需要拍板的 1-2 个问题，给选项>
```

## 决策汇总表（提案 §决策汇总）

| 编号 | 事项 | 建议默认 | 若不采纳的后果 |
|---|---|---|---|
| A1 | fin_transaction 补对手方/方向/账户字段 | 全量采纳 | **9 条规则无法实现，验收挂** |
| A2 | sys_user 补身份证/手机号 | 采纳 | RW-016/018 无法实现 |
| ... | ... | ... | ... |

## 状态分级（正文用）

- 🔴 **P0/最高优先**：不决策无法开工（数据模型、名单数据源、调度方案、拦截语义）
- 🟡 **中优先**：影响交付质量（映射、幂等、补偿、测试数据）
- 🟢 **低优先**：口径确认（窗口、演示路径）

## 注意事项

1. 每条决策点给 **a/b/c 选项**，不要开放式提问
2. 后果要写"验收会挂 / 规则永不触发"这类**可验证的失败**，不要写"影响体验"
3. 附"风控域承诺"小节（对齐后我方交付什么），让提案是双向的
4. 重点拍板项单独标出（建议 ≤6 项），其余可会后异步确认
5. 时间线：D1 上午拍板 → D1 下午改 DDL → D2 名单落地 → D3 机制联调
