# 一次真实闭环的完整证据（样例）

> 来源：2026-09-26 女仆家族玩法手册的一轮产出（正文生成 → 机械质检 → 修工具/修产物 → 复测）。
> 用途：写「趋势档」或向用户汇报质检时，照这个颗粒度给证据；也用于说明「为什么必须先怀疑工具口径」。

## 一、第一次自检：报 3 处硬伤（产物真错）

```
check_reply.py → 正文 892 字 ｜ FAIL=3
❌ [C1] 正文字数 892 < 1000（结算段已排除）
❌ [C2] 全篇零 emoji
❌ [C5] 结尾没有菜单（应为 1–4 条后续选项）
✅ [C7] 无 AI 味禁用词  ✅ [C8] 无高频短语重复  ✅ [C9] 正文无结算语  ✅ [C4] 主人留白 OK
```

同时量化脚本给出文笔画像与建议：

```
style_report.py → 正文 892 字 ｜ 句均长 11.9 ｜ 短句 45.3% ｜ 对话比 9.5% ｜ 五感 5/5
同轮高频：了一×11、她的×7、一下×7、了一下×5、压开×5、时候×5
建议：换词或换意象；意象「布」出现 9 次 → 单一意象过载
```

**处置**：产物真错 → 加长正文（补一个「加码单元」而不是灌形容词）、在情动/破功处补 emoji、替换 4 组高频词。

## 二、第二次自检：只剩 1 处，且是**工具口径**问题

```
check_reply.py → 正文 1002 字 ｜ FAIL=1
✅ [C1] 1002 字  ✅ [C2] emoji 4 个  ❌ [C5] 结尾没有菜单
```

- 「缺菜单」的原因：菜单本就在回复正文之外，检查时只喂了「正文本体」。**结论：自检要喂完整交付物（正文＋后戏＋菜单），或让工具的切分函数明确知道菜单也算交付物的一部分。**
- 同时发现两个工具对 emoji 的计数不一致（`check_reply` 4 vs `style_report` 2）→ 根因：基码位 ❤ 与变体选择符 VS16 被分别计数。

## 三、第三次：仍 FAIL 一次，仍是工具口径

```
❌ [C9] 结算语入侵正文（EXP/开发度/+数字 应只在结算段）
```

- 原因：元信息段（③ 记录：脚 20%→26%、EXP 20→40）**没有具名标记**，切分函数识别不到 → 把结算数字当成正文违规。
- 修法：给该段加标记 `—— 结算与档案 ——`（切分函数已支持 `—— 结算`）。

## 四、第四次：PASS（才允许交付）

```
check_reply.py → 正文 1139 字 ｜ FAIL=0 WARN=0
✅ 字数 / ✅ emoji / ✅ 菜单 4 条 / ✅ 无 AI 味 / ✅ 无高频重复 / ✅ 无结算语入侵 / ✅ 留白 OK / ✅ 档位估计
```

## 五、顺带修掉的两个「工具自身」缺陷

1. `check_reply.py` 的 emoji 计数把 ❤ 与 VS16 算成两个 → 改为共享正则 `[❤💦😈😵🥺♡]️?`，并与量化脚本统一。
2. 量化脚本 `--self-test` 第一次 **FAIL**：不是脚本错，而是**测试样本设计错**——「平静样本」自己全是短句，导致「激烈样本短句比例更高」这条断言无意义。把平静样本改成多处长句后自测 PASS。

## 六、可复用的汇报口径

交付时给用户的质检行应当**同时给数字与结论**，而不是「已检查通过」：

```
自检：check_reply PASS（正文 1139 字 / 菜单 4 条 / AI 味 0 / 留白 OK）
       style_report 已记录本轮：句均长 11.9、短句 44%、五感 5/5、意象「布」偏多（下次换）
```

## 七、本次教训的浓缩

1. 人眼复读两遍没发现的问题，机械检查一次抓出 8 项 → **生成类产物必须过机械质检**。
2. 三次 FAIL 里有两次是**工具口径**而非产物问题 → **失败先怀疑工具**。
3. 口径问题几乎都出在**边界**：分段标记、变体选择符、解析范围、主值 vs 说明。
4. 修完必须**复测**并留输出，否则「改了」无法证明「好了」。
