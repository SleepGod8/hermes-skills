# 状态档案回写一致性：字段 vs 备注（落档质检）

> 适用：产物不是一次性文章，而是**会被反复追加的状态档案**（账本、面板、台账、进度表、项目状态库）。
> 这类产物的质检和文章不同：它没有"读者读完就完了"这一层，**下次任务会从它继承状态**——写歪一次，后面每一轮都跟着歪。
> 来源：2026-10-29 一次真实会话（8 实体 × 动态面板，落档 5 次，踩到 2 个不报警的坑）。

---

## 一、两个坑（都是"校验 PASS 但档案是错的"）

### 坑 1：状态字段里做了排版强调 → 校验解析器读不到

| 项 | 内容 |
|---|---|
| 现象 | 校验脚本报「某字段格式异常（WARN）」，但人工看数字完全正确 |
| 根因 | 字段写成了 `秘处: **18**/0`（Markdown 加粗），解析器只认裸数字 |
| 修法 | **属数值的状态字段一律裸写，不加粗、不加 emoji 包裹**；强调只用在正文叙事里 |
| 验收 | 改完重跑校验，期望 `FAIL=0`，只剩"已登记例外"的 WARN |

> 推论：**任何"给人看"的排版手段，都会变成"给脚本看"的噪音**。状态字段是机器与人的共同接口，保持最小语法。

### 坑 2：备注写了累计变化，上方字段没跟着改（校验不报）

| 项 | 内容 |
|---|---|
| 现象 | 校验全 PASS，下次接手时数字自相矛盾——备注写「+18，现 18」，上方字段还停在 `0` |
| 根因 | 落档时先写备注（叙述性强、写起来顺手），忘了回头改状态字段；而校验器只校验"字段内部一致"，不校验"字段 vs 备注" |
| 修法 | 固定写回顺序（见下）；**备注里出现的每个累计值，必须能在上方字段里检索到** |
| 加强 | 在备注末尾写「现值 X」；校验器可加一条检查：备注中 `现 X` / `现为 X` 的数值必须在字段中出现 |

---

## 二、固定写回顺序（照这个顺序做，别倒过来）

```
① 备份（快照到工作区外，含源与全部副本）
② 改状态字段：计数 / 累加值 / 等级 / 装备 / 部位统计 …
③ 追加备注：写清「本次变化 + 现值 X」
④ 归档维护（条目超上限时按无损规则搬运，幂等可重跑）
⑤ 同步副本（单向镜像；有漂移就拦下并显式确认）
⑥ 跑校验（FAIL=0；WARN 必须能解释）
⑦ 抽样回读：随机挑 2 个字段，肉眼对一次"字段 vs 备注"
```

第 ⑦ 步是关键：**校验器只能证明它检查过的东西**。字段与备注之间的一致性目前没有自动检查，只能靠一次回读。

---

## 三、把"重复性"验证过一次

- 同批写的两个实体，字段口径必须**同名同义**（一个写「存量」，另一个写「余额」＝未来必然对不上）。
- 单位写进字段名或值里（`65 ml` / `65 条`），不要靠上下文猜。
- 一次操作涉及多个实体时，**每个实体各自点名"改了什么"**，不要用"以上同步更新"打包。

---

## 四、交付时的报告格式（这段比数字更防坑）

```
本次落档：
- 实体 A：字段 X 12 → 18（现值 18）；备注已追加（10/29）
- 实体 B：无改动
校验：FAIL=0 ／ WARN 1（已登记例外 C5，待裁决）
同步：N/N 一致，DRIFT 0，幂等复跑 unchanged
回读：抽查 A 的 X 字段与备注一致 ✅
```

不写"已更新全部档案"——那句话后面一定跟着一个漏掉的实体。

---

## 五、自检清单

- [ ] 状态字段没有加粗/emoji 包裹
- [ ] 每个累计值都改了上方字段，备注里写明现值
- [ ] 多实体改动逐个点名，没有"以上同步"
- [ ] 单位写在值里
- [ ] 归档/同步/校验三步都跑过，输出留档
- [ ] 做过一次随机回读（字段 vs 备注）
