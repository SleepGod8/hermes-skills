# 知识库体量审计与合并瘦身

用于**任何越写越肥的知识资产**：skill 库、设定集、runbook 集、文档站、参考资料目录。用户的抱怨通常是「太多太杂／太冗余／设定太多」——这不是审美问题，是**可量化的工程问题**：先量、再提案、再动刀、最后能证明没丢东西。

## 触发条件

- 「设定/玩法/文档/skill 是不是太多了」「过于繁多冗余」「检查一下体量」「瘦身」「精简」
- 「这几本手册内容重复」「合并同类项」「索引太乱，找不到」
- 库的自评指标全 PASS，但用户仍说「写得不到位」「太重」（→ 指标没对准症状，见 §5）

**不适用**：只要求新增内容；只改一份文件；库还小（< 30 文件 / < 10 万字）时直接改，不必上流程。

## 铁律

1. **先量后说**：结论必须带数字（字数、占比、相似度、使用次数），不许凭感觉列「可以更简洁」。
2. **只问「检查」就只出草案**：审计＋三档方案（合并／冷藏／索引化），**不动文件**；用户点选后才执行。
3. **原件不删**：合并件上线、原件进 `_legacy/`，任何人可回滚对照。
4. **报告分三栏**：文件数变化 / 字数变化 / 日常加载量变化——**结构优化 ≠ 字数优化**，不要把前者说成后者。
5. **改完必须跑库自带校验器**，并说明新增白名单（例：`_legacy/` 不参与索引登记）。

## 工作流

### 1. 量化审计（四张表）

```bash
python scripts/bloat_audit.py --root <库目录> --corpus <备注/日志目录> --keywords 玩法A,玩法B
```

| 表 | 指标 | 读法 |
|----|------|------|
| T1 | 每文件字数 + 按目录小计占比 | 占比 > 25% 的目录＝肥肉层 |
| T2 | 跨文件逐字重复行（≥18 字，≥2 文件） | 复制粘贴型冗余，最容易删 |
| T3 | 同目录 2-gram Jaccard 两两配对 | > 18% 的两本应合并或明确分工 |
| T4 | 关键词在 corpus 里的提及次数 | 0 次且 > 5,000 字＝冷冻候补 |

再看**结构倒挂**：设定/机制类占比 > 50% 而技法/范例类 < 10% → 库在长胖但没变强，必须调整。

实测参考（2026-10-29 某 79 文件 / 35.4 万字库）：面板存档 26.5%＋扩展玩法 25.2%，写作技法＋范例仅 6.7%；同目录相似度最高 21.9%（冻结↔感官遮蔽）；某手册 7,918 字、使用 0 次。

### 2. 出三档草案

- **A 合并同类项**：给出「哪几本 → 合成哪一本」，附每本一句话分工
- **B 冷藏区**：0 使用的手册移入 `_frozen/`，索引标「冷藏，需点名才读」
- **C 索引卡化**：主文件只挂 `触发词 | 一句话机制 | 路径`，细节按需打开

推荐组合通常是 A+C（B 视情况并入 A）。用户点名后才进入第 3 步。

### 3. 合并（可回滚七步）

备份整目录 → 按同类项分组 → 每组写 300–600 字**共用总则**（一张表讲清子项差在哪）→ 标题降级＋行级去重＋每册加「分册：原名（原文见 `_legacy/<原路径>`）」→ 原件搬 `_legacy/`（保留目录结构，不删）→ **路径重写（行级排除）** → 旧索引行换成索引卡。

细则、阈值、样例见 `references/bloat-audit-and-consolidation.md`。

### 4. 验证

1. 库自带校验器（如 `verify_*.py`）必须 PASS；若报「未登记」，先分辨是索引写法问题还是归档白名单问题
2. 残留旧路径检查必须为 0（排除 `_legacy` 与显式标注「原文见」的行）
3. 抽查一本合并件的分册顺序与指针是否指向正确原文件
4. 同步到子档案/镜像副本后再跑一次，保持 DRIFT 0

### 5. 指标要对准症状（血泪教训）

自评 PASS 不等于问题解决。反例：量「身体/描写词占比 68%」→ PASS，但用户要的是「具体性行为词密度」，实际只有 7.2/千字。

做法：
- 指标从**用户抱怨的原句**反推（「色情太少」→ 露骨度、机制代偿比）
- 用**被批评的那份样本**做双向验证：旧版必须 FAIL、改写版必须 PASS
- 阈值写进库的验收规则，并配可重跑脚本

## 交付格式

```text
结论：一句（含三个数字：文件数 / 字数 / 日常加载量）
证据：T1–T4 摘要表
执行：每组合并的来源 → 目标文件；原件归档路径；备份路径
验证：校验器结果、残留检查结果、同步结果（DRIFT）
未做：明确列出没动的部分与原因
下一档：要继续减字就做摘要级精简（预计可减 %）
```

## 坑表

| # | 现象 | 修法 |
|---|------|------|
| 1 | 合并件「来源」行全变成同一个文件名 | 先做路径替换，**后**写来源行 |
| 2 | 「原文见 `_legacy/X`」被替换成合并件名 | 路径替换按行排除 `_legacy` / `分册：` / `原文见` |
| 3 | 校验器报 N 个文件未登记 | 索引路径写全前缀（`references/...`）＋给 `_legacy/` 加白名单 |
| 4 | 合并后字数反涨 | 正常（共用总则＋内容保全）；报告分三栏并给下一档选项 |
| 5 | 用户只说「检查」却动了文件 | 违反铁律 2；审计阶段一律只读 |
