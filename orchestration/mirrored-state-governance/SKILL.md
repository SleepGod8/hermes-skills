# 镜像状态档案治理（多副本 / 多档案的状态数据）

处理一类特定的数据文件：**动态状态档案**——被反复追加、长期膨胀，且被**单向镜像**到多个档案目录（`profiles/<name>/skills/...`）。
典型例子：`lewd-playbook/references/面板存档/`（等级/开发度/装备/备注）、项目台账、任务台账、任何「子档案只读副本 + 主档案可写」的结构。

## When to Use（触发条件）

- 一个状态/档案文件**越来越大**（几十 KB 以上、备注条目越写越长），且每次互动/任务结束都要写它
- 数据被 `copytree` 镜像到多个档案（profiles），**不知道谁才是权威**、担心副本被改后丢失或分叉
- 出现「上次写的东西这次没了」「两个副本不一致」「校验脚本说没问题但其实没在比对」
- 主人要求：拆分归档、加校验脚本、加防篡改、把某批裁决落到档案里
- 承接 `self-improvement-governance` 的第 5 阶段（多档案同步）需要落地细节时

**不适用**：代码仓库的正常重构（用 `high-reliability-coding-workflow`）；单纯写文档；只要分析不要改动。

## 核心原则

1. **先备份，且备份到工作区外**（如 `E:\Hermes workspace\_backups\<task>_<ts>\`），含**源 + 全部副本**，不是只备份源
2. **无损拆分，不做压缩改写**：搬走的每条原文必须字节级保留，并**用计数比对证明**
3. **单一写入者**：一份状态数据只允许一个会话/进程写；副本一律只读 + 显著标记
4. **漂移默认拒绝覆盖**：副本被本地改过就拦下，要覆盖必须显式 `--force`，且覆盖前自动备份
5. **数据真伪交主人裁决**：发现自相矛盾时**禁止为消除报错而改数**，登记「规则例外表」并降级 WARN
6. **校验必须被证明有效**：写完校验器要用「故意破坏」验证它真的会 FAIL（否则可能是空转）
7. **幂等**：同一操作重复跑应报告 `unchanged`，而不是重写一遍
8. **子代理自报不可信**：委派产出的文件必须自己读回核对，数字要在素材里检索得到

## 阶段 0：备份与基线

1. 快照**源 + 每一个副本**到工作区外备份目录
2. 记录基线数字（各实体条目数）落成 `.baseline.json`——供「归档无损」校验用
3. 写清回滚方式（直接覆盖回备份目录）

## 阶段 1：审计（先取证，后建议）

禁止凭印象列问题。至少执行：

```bash
find "<root>" -type f -printf "%s\t%p\n" | sort -k2   # 体积分布，找膨胀点
grep -rn "<关键词>" "<root>" | head                    # 规则是否真的写在文件里
find "<root>" -name "*.md" | sed 's|.*/||' | sort      # 索引 vs 实际文件
```

**审计必查 8 项**（每项都要有证据）：

| # | 检查 | 证据形式 |
|---|------|---------|
| A1 | 单文件是否过大 / 备注是否无限膨胀 | 字节数与条目均长 |
| A2 | 索引表是否漏登记实际文件 | 路径集合差集 |
| A3 | 副本与源是否一致（含缓存污染） | 逐文件 md5 对比 |
| A4 | 是否存在「谁都能写」的副本 | 脚本写入方向 + 规则文本 |
| A5 | 校验/同步脚本是否有 dry-run / verify / 备份 | 读脚本 |
| A6 | 规则在**记忆**里但**没落进文件**（或反之） | 关键词在文件里出现 0 次 |
| A7 | 同一概念多处定义且互相矛盾 | 跨文件 grep 同一字段 |
| A8 | 薄文件是否违反「详细设定」标准 | 体积排名 + 结构 |

产出：**问题清单表**（ID / 发现 / 证据 / 影响 / 建议 / 优先级 P0-P2），向主人确认批次后再动。

## 阶段 2：无损拆分（总览 + 实体 + 归档）

```
状态目录/
├── <overview>.md        # 总览：通用规则 + 快速一览表 + 路由表 + 维护约定 + 单一写入者声明
├── maids|entities/<名>.md  # 每个实体一份权威副本（数值/状态 + 最近 N 条备注）
├── archive/<年月>.md    # 溢出备注的**全文**（无损搬运，不压缩不改写）
└── story-log.md         # 跨会话的「上次到哪／欠什么／下次钩子」
```

要点：

- **保留原文件名**作为总览（如 `panel-records.md`），避免旧引用失效
- 备注条目**按日期排序**后再 `keep N / archive 其余`——不要依赖物理顺序（原文件常乱序）
- 归档前缀写**原所属 section**，并在归档文件头写明「前缀＝归属，不是内容主角」
- 重复条目**如实保留不去重**（去重会丢失"谁记的"）

**无损证明（必跑，贴输出）**：

```python
from collections import Counter
print("缺失备注:", sum((Counter(o_rem) - Counter(new_rem + arch_rem)).values()))
print("缺失结构行:", sum((Counter(o_struct) - Counter(new_struct)).values()))
# 期望：0 / 0
```

## 阶段 3：单一写入者 + 镜像硬化

规则文本写进总览顶部与维护约定：权威源路径 + 唯一写入者 + 副本只读（副本侧结算只输出「报告」，由唯一写入者落盘）+ 原因（镜像单向，本地写入会被覆盖 = 会丢的数据）。

同步脚本必备能力（骨架 `templates/mirror_sync_template.py`）：

| 能力 | 说明 |
|------|------|
| `--dry-run` / `--diff` | 预演，不写任何文件 |
| `--verify-only` | 只校验副本与源是否语义一致，返回码可判 |
| `--force` | 覆盖副本侧漂移（覆盖前**必先备份**） |
| `--rebuild-baseline` | 基线不可信时重建（自恢复出口） |
| `.sync-manifest.json` | 上次同步的每文件哈希 + 时间戳 |
| 漂移检测 DRIFT | 副本哈希 ≠ 基线 ⇒ **拒绝覆盖**并列出文件 |
| `unchanged` 语义 | 语义一致就跳过，**不重写不备份**（幂等） |
| 只读标记 | 副本写 `_MIRROR_READONLY.md`，状态文件顶部注入只读横幅 |

## 阶段 4：校验脚本设计（骨架 `templates/verify_state_template.py`）

- **编号检查项** C1…C10 + PASS/WARN/FAIL 三级；FAIL 决定返回码
- 建议项：总览必备章节／实体文件齐全／索引行数／**总览与实体数据一致**／规则一致性（如「100% ⇒ 该状态」）／格式合规／条目数上限／**归档无损（对基线）**／索引覆盖所有文件／脚本可编译
- **提取口径（血泪）**：判定值只取**行首主值**或**剔除含「备注/裁决/素材/来源/说明」关键词的括号段**；否则你自己写的溯源说明会把判定带偏
- **解析器只解析它该解析的那一段**：`## 一览表` 与 `## 路由表` 常共用列结构，后出现者会覆盖先出现者 → 比对静默空转

## 阶段 5：规则例外登记（裁决闭环）

数据自相矛盾时**不要改数**：

1. 建 `<root>/rule-exceptions.md`：`ID | 实体 | 冲突内容 | 证据 | 待裁决选项 | 状态 | 影响校验`
2. 校验脚本 `parse_exceptions(check)`：该实体在该检查项上**降级 WARN**，不再 FAIL
3. **汇报时单独列出来请主人裁决**（给 A/B/C 选项），不替主人选
4. 裁决后：先改实体文件与总览 → 把「影响校验」列写 `已结案`（自动解除豁免）→ 重跑校验
5. 裁决本身在实体档案留一条事实记录（谁、何时、改了什么、原值是什么）

## 阶段 6：三重验收（一个都不能省）

```bash
python scripts/<sync>.py --verify-only     # ① 全部 N/N 一致
python scripts/<verify>.py --verbose       # ② FAIL=0（WARN 需可解释）
python scripts/<sync>.py --dry-run         # ③ would-copy=0 unchanged=N（幂等）
```

**再加一次「篡改实测」**（证明 DRIFT 真有效，而不是纸面功能）：

```
① 在某个副本里故意追加一行假数据
② dry-run     → 期望：只有该副本被 DRIFT 拦下
③ 正式跑       → 期望：拒绝覆盖，且**不更新基线**
④ --force      → 期望：覆盖成功，备份里能查到那行假数据
⑤ verify-only  → 期望：全部一致，假数据已清除
```

## 阶段 7：委派子代理做「数据考古」（可选）

场景：把散落在别人条目里的历史事实重建到实体档案。派发要点：

- 一个子代理**只写一个文件**，明确禁止改其他文件、禁止跑同步脚本
- 给它：权威字段值（照抄，不许推算）+ 素材清单 + **逐行照用的模板**（含字段名与格式）
- 要求：每条事实**带日期与出处**；查不到写「未建档」；**禁止编造数字**
- 收回后**自己核验**：文件存在、字段格式过校验、关键数字能在素材里检索到、它标的「冲突」是否属实
- 子代理的「疑似 bug」要自己判真假：误判常因文档语义没写明 → **补文档，而不是改数据**

## 阶段 8：报告（照抄结构）

```
结果：完成 / 部分完成 / 阻塞
1. 审计发现与批次
2. 每批实际修改（含前后数字，如 50,490 字 → 4,893 字，缩 91%）
3. 新增/修改文件清单
4. 真实验证命令 + 输出摘要（贴关键行）
5. 多档案同步结果（N/N 一致）
6. 备份/回滚点（绝对路径）
7. 幂等性与污染检查
8. 待主人裁决项 / 剩余风险
```

## 已踩坑清单（按出现频率）

| # | 现象 | 根因 | 修法 |
|---|------|------|------|
| 1 | 首次同步把**所有**副本判为 DRIFT | 无基线时仍做漂移比对 | 无基线 ⇒ 走「首次镜像」，不拦截；同步后再落基线 |
| 2 | 同步被全部拦下后，下次仍误报 | 中断的同步也写了基线 | 只有 `skipped==0` 才 `save_manifest()` |
| 3 | verify-only 永远 diff（29 个文件） | 源用 raw md5、副本用「去横幅」md5，口径不同 | 比较与基线**统一**同一语义哈希函数 |
| 4 | 去掉横幅后仍 diff | 注入横幅时多插了一个空行 | 只在标题行后插一行，保证「删掉横幅 = 源文件」 |
| 5 | `--force` 覆盖后查不到被改内容 | 覆盖前没备份 | 覆盖前 `copytree` 到 `backups/<task>/<ts>/<name>/` |
| 6 | 校验「PASS」但其实没在比对 | 后置表格覆盖同名行（字典 key 覆盖） | 解析器限定在目标 section 内解析 |
| 7 | 判定被自己的溯源说明带偏 | 括号里「原素材 80%」被当成主值 | 取行首主值 / 剔除含溯源关键词的括号段 |
| 8 | 归档被误判为「前缀写错」 | 前缀是 section 归属，不是内容主角 | 归档文件头写明前缀语义 |
| 9 | 归档维护脚本重复搬运 | 未做幂等判重 | 用「去掉前缀的原文」比对已有条目 |
| 10 | Windows `py_compile(cfile=os.devnull)` 报错 | `nul` 不是常规文件 | 用 `compile(source, path, 'exec')` |
| 11 | 搬运后条目总数对不上 | 用 set 而非**多重集**比对 | 用 `collections.Counter` |
| 12 | 备注上限一加就 FAIL | 「裁决记录」被当成第 7 条备注 | 裁决/规则类记录写进「事实摘要」区，不占备注额度 |
| 13 | 别的实体的段落出现在错误的实体文件里 | **旧文件缺换行**（`…（可变形）## Eos（…）` 粘成一行），按 `##` 切分时子段跟着走 | 拆分后扫「不该出现的实体名」；校验器加一条 C12：**某实体不得出现在其他实体文件正文** |
| 14 | 备注条目排序乱、看起来数据倒挂 | **条目标题日期 ≠ 内容日期**（「8/16」条目里写了 8/20–8/26 事件）；EXP 升级清零未标注 | 定规则：日期以条目内首个日期为准、跨日写区间；升级必须在备注写「升 Lv.X」 |
| 15 | 校验器加新检查却不知有没有生效 | 新检查可能被例外豁免或被正则写错 | 新增检查项后**必须做一次真/假双向测试**（造一条该触发的数据验证 FAIL、一条不该触发的验证不误报） |
| 16 | 维护脚本重写文件时**吃掉文件末尾的小节** | 重写只重建「备注 + 历史归档链接」两段，其余窗口内容被丢弃 | 双保留：① 备注窗口内**非备注行**原样保留 ② 「归档链接块之后」的额外内容原样保留；改完用**临时目录 + 8 条备注 + 误插小节 + 末尾小节**做真实回归测试 |
| 17 | 只修了被报告的那一处 | 同类缺陷散落全库（本次「人数口径」22 处命中，涉及 8 个文件） | 修一处后**按模式全库扫同类**（`grep -rn "<数字>个<实体>"`），一次性处置：规范性文档改用**不依赖计数的表述**，历史记录保留原文+登记例外 |
| 18 | 知识库「规则很厚、成品为零」 | 只有规则层没有范例层 → **规则只能避免写错，不能传递手感**（本次实测：≥150 字成品段落 0 篇） | 每个资产库都要有 **范例层**（成品示范 + 每篇标注「技法命中」），并配**量化基线**（跑指标脚本把范例变成数字）＋趋势记录档；指标工具必须自带 `--self-test` 证明方向正确 |
