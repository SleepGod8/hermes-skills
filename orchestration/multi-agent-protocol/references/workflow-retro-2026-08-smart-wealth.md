# 2026-08 smart-wealth 项目复盘新增要点（协议 v1.7）

> 来源：2026-08-19 智能财富管家系统（smart-wealth）多 Agent 协作复盘（default 中枢 Hermes & Iris 执笔）。
> 覆盖场景：验收闭环、环境口径、日志噪音、运维类任务（恢复/关闭）、汇报格式。
> 全团队必须遵从；与 multi-agent-protocol / enhanced-pipeline / workflow-retro-2026-08 冲突时，以本档案为最新增量。

## 1. 验收状态机与待验收清单（G3/G7 强化）

**「完成 ≠ 已验收」。** 交付汇报后必须等待主人明确验收信号，才能关闭任务。

1. **任务状态新增「待验收」**：合法状态流补一支 `已完成 → 待验收 → 已验收 / 未通过`。未验收任务不关闭、不静默转新任务。
2. **A1/中枢维护待验收清单**：每次交付后把「交付物路径、实测证据、验收动作（主人怎么做）、状态」登记进 `.agents/task-board.yaml` 的 `pending_acceptance` 节；主人确认后置 `accepted`。
3. **不静默跳任务**：主人发起新任务时，若上一任务仍待验收，汇报里必须带一句「上项仍待验收：XXX」，不让验收事项被新任务淹没。
4. **验收待办定期汇总**：A1 或 default 每完成一批交付，主动向主人汇总待验收清单（编号/内容/验收动作/等待时长），避免悬置。

## 2. 环境口径登记表制度（G0/G2 强化）

**运维类环境事实（凭证、端口、启动命令、进程归属、stop 边界）是反复踩坑重灾区，必须登记成契约附件。**

1. 每个含运行态的项目，开工广播时登记 **环境口径登记表**（`.agents/env-registry.md` 或契约 `前提事实` 节）：
   - 登录凭证（用户名/密码/口径注意——如「customerB 而非 customer2」）
   - 端口与进程（服务名/PID/端口/启动方式/日志路径）
   - 启动命令（含 Windows 下 POSIX 写法失效的坑，如 `npm run` vs `export VITE_PORTAL_MODE=... && npx vite`）
   - stop 边界（脚本能停哪些、手动拉起的进程如何停、Docker 是否保留）
   - 缓存/数据口径（缓存键、TTL、权威数据源）
2. **用前必查，改后必更新**：任何 Agent 使用环境事实前先查登记表；发现登记错误立即更新并广播。
3. **验收/恢复/关闭类任务**：先读登记表再动手，禁止凭记忆或凭群聊旧消息推断环境事实。

## 3. 日志噪音分级与主因判定（G2/G3 强化）

**报错日志 ≠ 故障主因。** 掉线/故障排查必须先做噪音分离。

1. **已知噪音清单**：项目常见报错噪音（如 `biz_announcement 表不存在`、权限告警类）登记入 `.agents/noise-list.md` 或契约节；排查时先对照，命中噪音不阻塞主因判定。
2. **主因判定靠实测**：进程存在性（`tasklist`/`ps`）、端口探活（`curl /health`/`netstat`）、日志 mtime——不靠日志关键字猜。
3. **噪音可关闭**：确认噪音后，如影响观感应安排处置（建表/授权），不无限搁置；但处置与主因判定分离。

## 4. 运维类任务（恢复/关闭）进程台账与 stop 边界（G4/G5/G7 强化）

1. **进程归属双轨登记**：脚本拉起的进程 vs 手动拉起的进程分开登记（`start-demo.sh` 类脚本只能管理自己拉起的进程）。
2. **stop 边界写清**：`stop` 命令覆盖范围（只停本机进程？不动 Docker？）在环境口径登记表写明；关闭项目前先列全进程清单，确认脚本覆盖不到的进程手动停。
3. **关闭验收口径**：全部目标端口无监听（`netstat -ano | grep :port` 无结果）+ 支撑组件按主人意愿保留/停掉，两项分开汇报。
4. **恢复流程**：先探活确认死因（连接重置=进程没了 vs 超时=还在跑）→ 查登记表找启动方式 → 幂等启动（先确认未在跑）→ 探活+冒烟 → 全量自检 → 汇报。

## 5. 汇报四要素（G7 强化，防「已办妥」悬置）

交付/修复/运维汇报必须一次带齐，减少主人追问：

1. **交付物路径**：文件/接口/页面具体位置；
2. **实测证据**：真实命令输出（health 码、curl 结果、测试通过数、进程 PID）；
3. **验收动作**：主人怎么做才能验收（刷新哪个页面、调用什么接口、看什么结果）；
4. **待验收项清单**：本次还有哪些项未确认，明确等主人验收。

**禁止**只报「已办妥」三个字就结束；未附验收动作的汇报视为未完成汇报。
