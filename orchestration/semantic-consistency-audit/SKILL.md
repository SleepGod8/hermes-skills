# 语义一致性审计（多文件设定 / 状态档案）

> **一句话**：数值校验脚本只能告诉你「数字对不上」；本 skill 处理的是**数字全对、但两句话互相打架**的那一层。
> 适用对象：人格设定库、动态状态面板（等级/开发度/累积量）、项目文档套件、规格包——任何「同一实体散落在多个 md 里」的知识库。

## When to Use（触发条件）

- 用户说「一致性检查」「全修」「看看有没有冲突」「设定对不上」
- 校验脚本 PASS，但你读正文时发现同一件事有两种说法
- 刚做完裁决/改名/改日期/新增机制，旧记录还没跟着改
- 某条设定被后补的「速览/摘要/索引」覆盖，与全书素材相反
- 结构性维护之后（拆分、归档、镜像同步）需要证明「不只是数字对」

**不适用**：单纯数字不符（跑校验脚本即可）；纯文档写作；代码重构。

## 核心原则

1. **分层读全，不许抽查**：设定文件 + 摘要/速览 + 索引/一览表 + 时间线/钩子池 + 通用规则 + 组合索引，六层全读一遍再列问题
2. **先取证后结论**：每条问题给出「文件 + 原句」，不凭印象
3. **按杀伤力分组**：P0（会直接写错）／P1（数值与时间线）／P2（冗余表述）——汇报也按这个顺序
4. **建议先行、授权后动**：先给「准备怎么修」的摘要，用户点头再落盘；用户说「全修」才批量改
5. **归档文件不改写**：历史归档是字节级证据，口径冲突只在**现行文件**加注「以本行为准」
6. **改一条、读回一条**：批量 patch 也要在同一脚本里 `print` 每条结果，失败立即补
7. **最后必须双验**：数值校验器 PASS ＋ 镜像校验全一致，缺一不算完成

## 流程

### 1. 取证（一次批量读，别来回问）

```
设定文件（references/<实体>.md 或 docs/<模块>.md）
摘要/速览段（后补的那种）
声音/风格档案（台词库）
总览一览表（等级/EXP/状态行）
故事线 / 时间线 / 钩子池
通用规则文件（SKILL.md 或规范正文）
组合/交叉索引
```

### 2. 跑 14 项检查 → 逐条列证据

清单详解见 `references/consistency-checks-14.md`（P0 4 项 / P1 5 项 / P2 5 项，每项含症状与修法）。

### 3. 备份（工作区外）

```bash
BK="<workspace>/_backup_<主题>_<日期>" && mkdir -p "$BK"
cp <每个待改文件> "$BK/" && sha256sum "$BK"/* > "$BK/SHA256SUMS.txt"
```

### 4. 逐条修复（推荐用一个脚本跑完全部）

- 文本替换优先用**短而唯一的锚点**；若锚点是「标题行 + 紧随其后的列表项」，`patch` 常匹配失败 → 用 Python 读改写（见坑表 #3）
- 每条改动后立刻读回并在 stdout 打印 `OK/FAIL <标签>`
- 失败项单独重试，别静默跳过（静默跳过 = 报告撒谎）

### 5. 双验

```bash
python scripts/<verify>.py            # 应为 PASS（FAIL 必须回改，不许改数迁就）
python scripts/<sync>.py --verify-only # 应为 N/N × M/M 全一致
```

### 6. 汇报（结构固定）

```
一、机械层（脚本实跑结果，贴关键行）
二、P0 逐条：原文 → 改成什么 → 为什么
三、P1 逐条（含时间线补全、缺口补记）
四、P2 逐条（索引化/去重/措辞）
五、没动的文件 + 为什么不动（归档无损）
六、备份路径 + 回滚方式
七、待用户裁决的遗留项
```

## 已踩坑清单

| # | 现象 | 根因 | 修法 |
|---|------|------|------|
| 1 | 校验脚本全 PASS，用户仍觉得「对不上」 | 校验器只比对结构化数值，不读语义 | 每次设定扩容后跑一遍本 skill 的 14 项；把「语义层」写进维护约定 |
| 2 | 后补的「速览/摘要」与全书素材相反（如速览规定自称 X，正文全用 Y） | 摘要凭印象新写，没有回向素材核对 | **以素材（正文/台词/记录）为准**改正摘要，并在摘要旁留一条修订注说明「原写法已废」 |
| 3 | `patch` 报 `Could not find a match`，但文本肉眼一致 | 锚点太短或跨「标题行+列表项」结构，模糊匹配失败 | Python 读文件 → `find(marker)` → 插在 `\n` 之后 → `open(..., "w", encoding="utf-8", newline="")` 写回 |
| 4 | 改完用 grep 复核 emoji 内容，显示 0 命中 | MSYS/终端下 emoji 匹配会假阴性 | 用 Python `open().read()` + `in` 复核 |
| 5 | 状态时间线写「第二次／第三次」后越写越乱 | 序号需要人肉计数，漏一次就整体漂移 | **禁用「第 N 次」**，改「历次按日期列：9/24-2 ／ 9/24-6 ／ 10/10-2 ／ 本次」 |
| 6 | 同一数字写在两处（开发度行写「已射精 7 次」，统计行是 0/8） | 一个事实两个事实源 | 数字只留一处（统计行）；另一处改成「以统计为准」 |
| 7 | 改了某实体 EXP，校验器报 C4 不一致 | 只改了实体文件，没改总览一览表 | 改数值后**同步改一览表**，再跑校验 |
| 8 | 归档文件被「修」过，历史不可信 | 把口径修正写进了 archive | 归档只读；冲突在现行文件加注「以本行为准，归档原文保留」 |
| 9 | 钩子池（待办/未发生清单）挂着已经发生的事 | 事件发生后只更新了「第一次清单」，没清钩子池 | 每个「第一次」登记的同时，去钩子池把对应项移出并留修订注 |
| 10 | 同一机制两套阈值（A 文件 3 点崩、B 文件 2 次崩） | 两处各自演化 | 拆成**两条轴**（长期累计 / 单场即时）并互相引用，或合并成一套 |
| 11 | 共通规则与个例冲突（规则说「不会发生」，某角色因装备常驻） | 个例没登记例外 | 个例文件加「例外登记」小节，共通规则侧加一句指向；不删规则 |

## 新增/修改设定时的最低标准

用户明确要求过：**新玩法/新机制禁止一行简介入库**。八节骨架（照抄 `references/mechanic-spec-skeleton.md`）：

1. 一句话定义 + 定位（它是既有哪条机制的升级/分支）
2. 分型/分相（把用户的两句话拆成可独立驱动的两个相）
3. 辨识度（声音/触感/口头禅等独一无二的标记，必须可量化描述）
4. 强度分级（Ⅰ–Ⅳ：幅度/频率/本人状态/外在表现）
5. 阶段/阶（受方视角的三阶递进）
6. 联动（与既有机制逐条互锁，≥6 条）
7. 各角色表现表（谁在场会怎样，一人一句）
8. 名场面 3–4 个（可直接开演）＋ 红线与解除（最高优先级 + 上限 + 谁能中断）

写完 → 登记索引（总览索引行、组合矩阵、面板「专属能力」行）→ 双验。
