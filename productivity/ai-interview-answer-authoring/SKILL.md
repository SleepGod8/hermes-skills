# AI 岗技术面试问答撰写（结合项目文档）

用户（张树灿，求职 AI 应用/Python 全栈）经常贴出一道面试官追问，要求「结合 `<某项目目录>` 内文档回答」。
产物不是文章，是**可以直接说出口的话**：口述版 + 追问预备 + 边界声明。此任务会反复出现。

## 触发条件

- 用户贴出面试题/追问，要求结合某项目文档作答
- 要求"模拟面试""准备话术""这题怎么答"
- 维护 `E:\Hermes workspace\面试\HireMe AI 自定义指令.txt`（模拟面试工具的系统指令）

## 事实源（先定位，不要凭记忆答）

```
E:\Hermes workspace\面试\
├── HireMe AI 自定义指令.txt          ← 回答风格与事实边界的权威规则（先读）
├── 张树灿-AI工程师面试准备手册.docx    ← 3 分钟自述 + 高频题参考答案
├── 张树灿-HireMe AI知识库补充资料.docx ← 200+ 题目录，查这题是否已有现成口径
├── 张树灿简历-3年python全栈工程师.docx ← 姓名/公司/时间/职责范围的唯一事实源
└── ai-talent-platform\docs\           ← 需求/架构/API/数据库/测试/详设（另一份在 E:\Hermes workspace\ai-talent-platform）
```

**权威顺序**：简历（姓名/时间/项目/本人职责）> 项目文档（架构/流程/契约细节）> 面试手册（口吻与既有口径）。
项目文档只补工程细节，不改变简历事实；手册里的"参考答案"是压缩版，不要原文照搬。

## 硬约束（违反即失分）

1. **设计文档 ≠ 已上线 ≠ 实测**。任何数字只能属于三者之一；没有实测就写"设计目标/示例参数，需用真实数据标定"。
2. **不编造**模型版本、阈值、QPS、准确率、客户名、用户量、成本收益。
3. **规划不算交付**：Dify、Vanna.ai、PgSQL、实时语音等只能表述为"规划/二期/接口已预留"。
4. **区分个人负责 vs 团队/架构范围**：骨架、图谱、记忆、事件总线若是团队产出，就说"我可以解释它如何和我的模块交互"。
5. 不输出"以下是答案/根据知识库/建议这样回答"这类元话语，只给能直接说出口的内容。

## 输出形状（用户已认可的定式）

1. **「先说结论（可直接口述版，约 400 字）」** —— 第一人称口语，可带"嗯/其实/然后"，**不要**列"第一、第二、第三"，不要小标题塞进口述版。
2. **「追问预备表」** —— 表格：`追问 | 回答要点`，4-6 行，每行一句能独立成句的技术结论。
3. **「必须说清的边界」** —— 把文档里**真实存在的验收口径**摆出来（如"这题当时只有人工抽样 10 份 5 人 ≥4/5"），并明说上面那套是演进方案不是实测。这条最能加分，也是防止被反问穿的关键。
4. 结尾给一个可选下一步（落成一页设计备忘 / 补进 docs / 出三个变体），让用户决定是否继续。

## 工作流

1. `read_file` 读 `REQUIREMENTS.md`，**专挑验收指标那几行**——面试官问"你怎么验证"的答案就在这里。
2. `read_file` 读 `03-test-cases.md`，看 `*-A-*`（AI 质量）用例是怎么定义证据的。
3. `grep` 关键词找**已有机制**，不要发明新概念：`Schema|重试|一致性|采样|极差|阈值|词库|并集`。
4. 回答尽量由文档里**已有机制拼装 + 同构类比**："这跟合规扫描那套两层并集是同一个思路"。比凭空设计可信一个量级。
5. 写口述版 → 追问表 → 边界。长度按 HireMe 指令：普通题 80-180 字，项目题 250-450 字，追问只答新增细节。

## 答题范式：分层，不要二选一

面试官抛"用规则硬匹配还是引入新 Agent"这类二分题时，标准答法是**分层递进**，并给出每层的职责边界：

```
契约层（Schema/Pydantic）→ 只保证格式，不保证语义
确定性规则层 → 高精度、零成本、可回归，做必过闸门
语义评估层（独立 Agent/LLM）→ 覆盖规则抓不住的含义，高召回、非确定性
回归与指标层 → 固定评测集 + 人工兜底低置信度
```

一句话主线：**规则做高精度闸门，模型做语义覆盖，两层取并集，人工只处理低置信度那部分。**

## 常见追问与正确口径

| 追问 | 口径 |
|---|---|
| 为什么不纯用 LLM？ | 成本、非确定性、不可回归，且与生成同模型会自我确认偏差 |
| 规则误报怎么办？ | 受控词表/闭集映射，映射不上只告警不拦截，误报率设上限 |
| 怎么证明它变好了？ | 正负样本集（人工注入坏例）跑 precision/recall，改 Prompt/换模型都回归 |
| 批量不重复烧钱？ | 任务队列 + 幂等键，同一版本不重复评审，结果落库可审计 |
| 为什么不微调？ | 有 RAG/规则/结构化输出能解决的先不微调，行为长期稳定再评估 LoRA/SFT |

## 坑

- **口述版写成技术文档**：小标题、编号列表、"综上所述"一律删掉，用连续口语。
- **把验收目标当实测结果**：文档里的 ≥99%、≥4/5 是**验收目标**，说成"我做到了"必被追穿。
- **只读需求文档就开答**：测试用例和生产代码口径才能暴露"这题实际有没有做"，两者都要看。
- **照搬面试手册的参考答案**：那是给 AI 的压缩口径，缺细节且更适合机器检索，不适合口述。
