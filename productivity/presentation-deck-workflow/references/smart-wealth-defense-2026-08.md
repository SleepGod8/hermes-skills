# 实战样例：智能财富管家 答辩 PPT 规格 v1（2026-08）

> 首个 presentation-deck-workflow 实战。项目：E:\项目\smart-wealth（金融多 Agent 系统，答辩场景）
> 状态：规格 v1 已完成并交主人审阅，生成/QA 待主人确认后执行

## 项目关键事实（来自深读文档）

- 定位：金融多 Agent 系统。统一执行骨架 AgentBase + 5 个业务 Agent（客服/投顾/分析/操作/风控）+ Redis 事件总线 + 四层记忆 + IAM 权限模型
- 技术栈：FastAPI + MySQL8（10 核心表）+ Milvus（3 集合）+ Neo4j + Redis + MinIO + LLM；双门户前端（8080/8081）；Docker 微服务
- 核心技术组件：RAG（Milvus 向量检索 + 来源引用）、GraphRAG（Neo4j 多跳 + 融合排序）、NL2SQL、NL2API（8 意图 + RBAC + 二次确认）、置信度引擎
- 四层记忆：短期（Redis 会话 30min）/中期（画像缓存 7 天）/长期（向量+图谱）/归档（conversation_archive）
- 风控（张树灿主场）：20 条规则引擎（反洗钱 V2.1）→ 分级预警 蓝/黄/红 → 工单 → 事件广播；唯一被动触发型 Agent
- 操作（胡浩）：8 意图 NL2API，二次确认阈值 申购>1万/赎回>1万份/转账>5万，前置校验（金额≤120%总资产/适当性）
- 评分标准：P1 基建+客服 15% / P2 画像+NL2SQL 20% / P3 图谱+投顾+操作 20% / P4 风控+记忆 20% / P5 集成 15% / 答辩表现 10%
- 加分项（最高+20）：架构设计+5 / 创新功能+5 / RAG效果+3 / GraphRAG深度+3 / 前端+2 / 代码质量+2
- 答辩时长：5 分钟 PPT + 7 分钟演示 + 3 分钟问答 → PPT 12-14 页

## 规格 v1 页面规划（14 页）

```
1  封面        项目名 + 智能财富管家系统 + 团队名（深色金融风）
2  目录        五大部分导航
3  背景与痛点   人工客服慢/投顾凭经验/风控人工抽查漏 → 对比表
4  项目定位     不是5个聊天机器人，是"一个营业厅"——5 Agent 共享档案与事件流
5  系统架构     分层架构图（前端/网关/编排/组件/工具/存储）
6  五大 Agent   职责矩阵表（服务对象/能力/技术/是否碰钱）
7  核心技术①   RAG + GraphRAG 双检索（向量检索 + 图谱多跳融合）
8  核心技术②   NL2SQL + NL2API（自然语言→SQL/API→安全校验→执行）
9  数据架构     10 表 + Milvus 3 集合 + Neo4j + Redis 事件总线
10 风控监测    20 条规则 → 分级预警（蓝/黄/红）→ 工单 → 广播 【主人主场】
11 业务操作    8 意图 NL2API + RBAC + 二次确认 + 前置校验 【主人主场】
12 四层记忆    短期/中期/长期/归档 + 置信度衰减（加分项）
13 工程实践    Git 规范 / 测试 / 故障降级 / IAM 最小权限
14 总结与展望  成果 + 不足 + 改进方向
```
