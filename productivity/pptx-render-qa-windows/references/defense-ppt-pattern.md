# 答辩 PPT 设计模式（Defense PPT Pattern）

> 来源：2026-08 smart-wealth 项目答辩 PPT 实战。通用模式，适用于任何课程设计/毕设/项目答辩。

## 核心原则

答辩 PPT 不是「介绍系统」，而是「**证明工程能力 + 踩中评分标准**」。先读评分标准，再倒推页面设计；生成后用问答预测反向补防守点。

## 模式流程

```text
① 读评分标准（答辩表现权重、各模块权重、加分项、扣分项）
② 按权重倒推页面：权重 20% 的模块必须专页；加分项单独提
③ 设计页数 = 答辩分钟数对应的页数（5分钟 → 12-15 页，每页一个核心观点）
④ 生成 PPT（pptxgenjs + 本技能渲染 QA 闭环）
⑤ 用强模型做「问答预测」（18 题：评委最可能追问 + 连续追问链）
⑥ 按问答预测反向补防守点 → 修改 PPT → 重新渲染 QA
⑦ 同步输出讲稿节奏（时间分配到秒，对应每页）
```

## 问答预测的题目分类框架（可复用）

| 分类 | 考察点 | 典型问题 |
|------|--------|---------|
| 域深度追问 | 是否真懂自己负责的模块 | 规则边界重叠？置信度哪来？幂等怎么防？ |
| 架构选型 | 为什么这么设计，是否堆砌 | 为什么 N 个 Agent？为什么 N 种存储？ |
| 安全合规 | 安全边界是否真在服务端 | RBAC 是前端隐藏还是后端校验？注入怎么防？ |
| 跨组件协作 | 是否理解可靠性局限 | Pub/Sub 丢消息？事件循环？数据不一致以谁为准？ |

## 问答预测回答结构（GPT-5.6-sol 实测有效）

每个问题按「**结论 → 实现要点 → 证据**」回答，并附「易踩坑」：
- 结论先行一句话（如「命中 3 条按红色处理，红色优先」）
- 实现要点具体（规则编号、阈值、状态流转）
- 证据可展示（测试记录、工单、trace_id 链路）
- 易踩坑提醒（不要说「Prompt 约束了模型」——Prompt 不是安全边界）

## 本轮实战暴露的 6 类防守点（直接往 PPT 补）

1. **规格边界重叠**（如「2-3 条黄 vs ≥3 条红」）→ PPT 显式写「红色优先」，消除歧义
2. **概念澄清**（置信度不是模型概率）→ PPT 加一句定义
3. **可靠性诚实**（Pub/Sub 不保证不丢）→ PPT 写「事件持久化 + pending Set 补偿」，主动承认边界
4. **幂等/防重**（资金操作）→ PPT 写「请求标识 + 状态流转」
5. **记忆权威性**（记忆不是交易权威源）→ PPT 加警示「执行时回源 MySQL」
6. **完整业务链**（加分策略核心：一条 trace_id 贯穿的链路页）→ 新增专页

## 加分策略（问答预测产出，直接指导 PPT 结构）

- 5 分钟答辩时间分配：40s 全貌 → 1m20s 一条完整业务链 → 1m 主动展示失败用例（红线拦截）→ 1m 可解释性（规则命中明细）→ 1m 可靠性与边界意识
- PPT 页面保留三个「技术证据」：20 条规则的命中明细、二次确认状态流转、停机后 pending 补偿结果
- 主动引导评委问自己的负责域（演示失败用例比展示成功页面更能证明系统可控）

## 通用性说明

该模式不限于 smart-wealth：任何有评分标准的答辩（毕设/课设/比赛）都能套用。核心是**把评委的追问链提前在 PPT 里堵住**——问答预测发现的漏洞，就是 PPT 需要补的防守点。
