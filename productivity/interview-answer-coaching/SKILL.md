# 面试答题辅导（候选人视角代答）

主人（张树灿）在求职期会把面试官的问题直接丢过来，要一段**能照读出口**的回答。
不是技术咨询，是替他写话术。答得再深，只要不像人说的是失败。

## 触发

- 「这个问题怎么答」「你会怎么写」+ 某项目背景
- 明确点名结合某目录文档（`E:\Hermes workspace\面试\<项目>` / `E:\项目\smart-wealth`）
- 反复出现的追问：「回答简短一点」「口语化」「再短」

## 硬规则（被主人纠正过的，别再犯）

| 规则 | 具体要求 |
|---|---|
| **短** | 口述版 200–300 字。第 3 次被要求"再短"就是前面全写长了 |
| **口语** | 第一人称，可少量「嗯、其实、然后」，像在说话不是在写文档 |
| **无表格** | 主人要的是"能说出口的话"，表格塞不进嘴里。判定矩阵/对比表只在技术备忘里给 |
| **无分层清单** | 不写「第一/第二/第三」，不写 ①②③，用连接词带过 |
| **无元话语** | 不说"以下是答案/根据文档/建议这样回答" |
| **先给结论再给理由** | 第一句就是判断，不要铺背景 |
| 先给答案，后给可选补充 | 主答之后可问一句"要不要拆开讲"，别默认展开 |

**识别到这些信号就立刻收短**：「简短一点」「口语化」「回答简短口语化」＝当前版本已超长一倍。

## 工作流

1. **读真文档**。项目相关的每个事实都要能在文档/代码里找到出处，别用通用 LLM 知识冒充项目经历。
   - 人才平台：`E:\Hermes workspace\面试\ai-talent-platform\docs\`（REQUIREMENTS / 02-api / 03-test-cases / 06-detail-design）
   - 就业教练：`E:\Hermes workspace\面试\job-coach-platform\docs\`
   - 财富管家：`E:\项目\smart-wealth`（有真实代码，`app/tool/bus.py`、`app/utils/logger.py` 等可引真实现）
2. **抓项目特有的机制做答**，别给泛泛的行业答案。例：合规扫描的"规则+LLM 两层取并集"可以直接复用到 JD 自洽性检查；M3 的"低温 5 次采样取中位、记极差"可以直接回答一致性题。复用项目内已有机制 = 可信度最高。
3. **写口述版**（200–300 字，短句）。
4. **补一句边界**：设计文档 ≠ 上线实测。没有实测数字就明说"这是设计思路/示例参数，要拿真实数据标定"。这句话在面试里是加分项，不是减分项——证明知道验收口径的边界。
5. 追问预备**不要默认展开**。主人要的时候再给。

## 事实边界（不许越线）

- 不说生产客户、真实用户量、QPS、准确率、成本收益、上线状态，除非简历/文档写明。
- 区分：个人主责 / 团队协作 / 规划二期。财富管家的统一事件总线、Agent 骨架、知识图谱属架构组范围；他主责风控与业务操作。
- Dify、Vanna.ai、PgSQL、实时语音 = 二期/规划；BM25、RRF 未出现在材料里只能说通用方案。
- 阈值（采样次数 5、极差 ≤1.0 档、温度 0.2）在人才平台/就业教练文档里是**验收目标**，不是生产实测值。
