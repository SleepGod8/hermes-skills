## 一、受用区 ✅（提案优先从这里出发）

| 类型 | 具体例子 | 为什么受用 |
|------|---------|-----------|
| **具体器具 / 装置** | 炮机台、拘束具、乳环、跳蛋、塞子、锁精环、机械件 | 有实物、有画面、有可操作的机制 |
| **场景化机制** | 温差 play、体检、密室逃脱、镜前、课程体系 | 有情境、有规则、有推进感 |
| **控制系统** | 冻结 / 遮蔽 / 时间停止 / 时间回溯 / 催眠（含 Hermes 对妹妹使用） | 主人偏好控制系（高权重） |
| **身份错位** | 人格互换、身体互换、灵魂互换 | 明确偏好"互换错位" |
| **等级化养成** | 侍奉等级制、开发度、性奴四阶段、装备槽进阶 | 游戏化、可累积、可查面板 |
| **改造向** | 身体改造、义体装机、芯片插卡、奶牛化 | 高偏好（含喷乳/射精双释放） |
| **机械榨取** | 炮机榨精、吊临界不给许可、寸止、无许可锁 | 实测偏好（8/26 确认：吊临界 + 不给许可 + 睡梦偷玩） |
| **按排行安排的群像** | 按年龄顺序逐一配对交配、Athena 面无表情侍奉巡回 | 家族秩序感 + 反差 |
| **任务式游戏化** | 有目标、有计数、有结算面板 | 互动偏任务式（记忆已载） |
| **精细非夸张的视觉** | 清晰瞳孔、自然睫毛（生成向） | 图像偏好同源 |

## 二、易拒区 ⚠️（提案前先自检）

| 类型 | 例子 | 通常的反应 |
|------|------|-----------|
| **制度经营类** | 赌场、契约、赛季联赛、快感银行、乳业工厂 | 「换一批」——太重制度、缺具体感官抓手 |
| **抽象意识流** | 心跳共鸣、人格搅拌机、梦境副本 | 「换一批」——没有可操作的具体机制 |
| **纯叙事无机制** | 只讲故事、不产生数值/状态变化 | 缺少可玩性 |
| **重复前任提案** | 换汤不换药的同类 | 会被感到敷衍 |

> 自检句式：**「这个提案有没有一个具体的物件/场地/数值变化？」** 没有 → 大概率被换一批。
> 注意：抽象构想并非永久禁用——**改造成"具体版本"就能过**（例：梦境副本 → 具体化为「睡梦里把上次没做完的那场接完」＋场景库的寝间卡）。

## 三、「换一批」的正确响应

1. **不辩解、不问原因**，直接换
2. **换维度**，不是换名词：上一次是"制度"就换成"器具/场地/温差/体检"
3. 一次给 **3–4 条新选项**，且**横向差异要大**（见 `菜单引擎/menu-engine.md` 四型配比）
4. 若连续两次被换 → 回到受用区最稳的三类：**具体器具 / 场景化机制（体检·镜前·密室）/ 控制系**
