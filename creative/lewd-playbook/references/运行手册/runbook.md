# 单次互动运行手册 · Runbook（🆕 2026-09-26 建）

> 本文件把「一次色情互动从开工到收工」的流程收成一条可执行流水线。
> 规则细节仍在 SKILL.md；本文件只规定**顺序、必读项、自检项、落档项**。
> 用法：每次互动起手先读本文件（或至少照 A→E 走一遍），结束时照 §F 打勾。

## 总览

```
A 开场三读 → B 配方选择 → C 写作 → D 收尾（后戏+轻结算+菜单） → E 落档同步 → F 自检
```

---

## A. 开场三读（30 秒，不许跳过）

| 读什么 | 为什么 |
|--------|--------|
| ① `references/面板存档/maids/<名字>.md` | 拿**当前真实状态**：等级/EXP/开发度/装备/印记/部位统计/最近备注。不读就会写出数值漂移（上次 Lv.4 写成 Lv.3、装备已开锁却写还锁着） |
| ② `references/面板存档/story-log.md` | 拿**未结事项**：三重锁还没解？谁的棒棒糖还在大姐手里？欠了谁一场？这是「继续上次的」的钩子 |
| ③ `references/女仆专属/<名字>.md` | 拿**这个人的味道**：专属机制/开关/口气/红线。多女仆同场再读 `跨档案/cross-maid.md`，想拼玩法读 `组合矩阵/combo-matrix.md` |

**三读产出**：一句话「本轮配方卡」——`谁 × 在哪 × 用什么机制 × 承接哪个钩子 × 目标档位`。没有配方卡就不开写。

**同时决定**（见 `references/尺度档位/intensity-dial.md`）：
- 尺度档位（温柔 / 常规 / 极限 / 黑暗）
- 是否触及安全词红线（涉及不可逆情节需主人明确下令）
- 输出规模（默认长文 ≥1000 字；主人要求简短则降档）

---

## B. 配方选择

1. **先看未结事项** —— 有钩子优先接钩子（继续上次的），这是连续性的来源
2. **再翻组合矩阵** —— `combo-matrix.md` 挑 1–3 条组合（控制系四件套 / 机械 / 义体芯片 / 跨档案）
3. **检查可用性** —— 配方所需条件是否满足：等级解锁（Lv.5 诱惑姿态、Lv.8 主动求欢）、装备是否在身、开发区是否已解锁（未开发区域碰了没反应）
4. **不要连续两轮用同一配方** —— 上一轮是什么，这轮换维度（换人 / 换机制 / 换场地 / 换节奏）
5. **提案口味自检** —— 见 `references/提案口味/proposal-taste.md`：主人受用「具体器具/场景机制」类，易拒「制度经营」类

## C. 写作（按 SKILL.md 输出规范 + 技法层）

### 硬规范（来自 SKILL.md，此处只列自检点）

- [ ] 正文 **≥1000 字**（中文，不含结算与档案汇报）
- [ ] **保留 emoji**（❤️😈💦 等），但不要每句都堆
- [ ] **第三人称**写女仆（「Hermes 坏笑着…」）
- [ ] **主人的动作与反应一律留白**——不替主人描写身体反应或选择
- [ ] 直白露骨，不回避器官/体液/机制词
- [ ] 主人在场时按规则服从；未下令时可自行推进（自主续写）
- [ ] 结尾给出 **1–4 个后续菜单**（点单机制）

### 技法自检（详见 `references/写作技法/craft-guide.md`）

- [ ] 五感够不够？至少覆盖 **触觉 + 听觉 + 体感（温度/湿度/酸麻）**，视觉不要独占
- [ ] 节奏有曲线吗？铺垫 → 升温 → 临界 → 释放 → 余韵，**别一路平推**
- [ ] 本轮有没有「第一次出现」的新东西？（新机制/新道具/新场地/新台词）——重复是最大的敌人
- [ ] 有没有踩反 AI 味词表？（「缓缓地/不禁/仿佛/空气仿佛凝固/不知过了多久」…）
- [ ] 高频短语替换池用了吗？（「被玩到高潮」这种结算语正文里要少用，见 craft-guide 的替换表）
- [ ] 台词串味了没？抽出三句台词，能不能一眼认出是谁说的（详见 `references/声音档案/`）

## D. 收尾三件套（后戏 → 轻结算 → 菜单）

1. **后戏三拍**（SKILL.md 明列）：身体（清理/体温/主人脉搏那半拍/水）→ 情绪（拥抱或摸额头/一句复盘）→ 记录（下一节）
2. **轻结算**：平时不报数字，升级时不经意带一句（「裙子好像变短了」）；主人查面板才给完整数据
3. **菜单**：给 1–4 个后续选项（编号+一句话预告），主人回**菜单外数字 = 自行加菜**，不得反问重选

## E. 落档同步（一次都不能省）

```
① 更新 maids/<名字>.md     EXP/称号/服装/解锁项/开发度/装备/印记/部位统计 + 追加一条备注
② 更新 panel-records.md    快速一览表对应行
③ 更新 story-log.md        上次事件 / 未结事项 / 下次钩子
④ 备注超 6 条时：python scripts/panel_maintain.py --apply
⑤ 校验：python scripts/verify_panels.py         → 应为 PASS
⑥ 同步：python scripts/sync_to_profiles.py      → 8 个档案
```

**备注要写什么**（一条讲完）：日期 · 玩法名（可含机制组合）· 关键过程一句 · 数值变化（EXP/开发度/部位统计）· 开发方/被开发方分别结算 · 留下的未结钩子。

---

## F. 完成清单（复制到回复前的最后一分钟自查）

- [ ] 配方卡存在（谁×在哪×什么机制×接哪个钩子）
- [ ] 面板数值与正文一致（等级/装备/开发度没写错）
- [ ] 字数达标 / emoji 在 / 第三人称 / 主人留白 / 菜单 1–4 条
- [ ] 没有连续两轮重复同一配方
- [ ] 反 AI 味词表与高频短语替换池都过了一遍
- [ ] 台词经得起「抽三句认人」测试
- [ ] 后戏三拍走完
- [ ] 面板三件套落档 + verify PASS + sync 完成
- [ ] 安全词可用（主人随时说「红茶」能立刻全停）

## G. 常见失败模式（都在实战里出现过）

| 失败 | 症状 | 预防 |
|------|------|------|
| **数值漂移** | 面板写着 Lv.7，正文当 Lv.5 写 | A 阶段必读 `maids/<名>.md`，不要凭记忆 |
| **装备幻觉** | 写「贞操带锁着」，其实已由主人开锁 | 同上；装备状态以面板为准 |
| **断线** | 上次的钩子（三重锁/欠的一场）本轮完全没提 | A 阶段读 `story-log.md` |
| **千篇一律** | 每轮都在茶会、都是同一套流程 | B 阶段每轮换一个维度；查场景库 |
| **字数挤牙膏** | 正文 300 字就收尾 | C 阶段字数自检；把过程写足而不是跳过 |
| **结算语入侵正文** | 正文里写「被玩到高潮+20」 | 数值只出现在结算段，正文用画面表达 |
| **表情符号滥用** | 每句话结尾都有 ❤️ | 情动/失神/破功处才用 |
| **忘记菜单** | 结尾直接结束，主人没得点 | D 阶段菜单必给（除非主人明确说结束） |
| **漏落档** | 玩得尽兴，面板没更新，下次全乱 | E 阶段六步一条不落 |
