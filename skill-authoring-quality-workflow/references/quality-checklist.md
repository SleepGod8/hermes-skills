# Skill 质量验收清单

使用时逐项勾选，并在交付报告中引用未通过项。`必须` 项未通过时，不得声明完成；`建议` 项可在风险可接受时延期。

## A. 触发与范围

- [ ] 必须：`name` 只含小写字母、数字和连字符，目录名与其一致，长度小于 64 个字符。
- [ ] 必须：`description` 同时说明能力和触发场景，包含用户可能使用的同义表达。
- [ ] 必须：至少有一个应触发的请求和一个相近但不应触发/应转交的请求。
- [ ] 必须：写明不适用范围，避免与现有 skill 竞争触发。
- [ ] 建议：记录与现有 skill 的关系、优先级和迁移方式。

## B. 契约与工作流

- [ ] 必须：输入的必填项、可选项、默认值、格式、大小和敏感信息规则明确。
- [ ] 必须：输出文件、字段、状态、错误和完成条件明确。
- [ ] 必须：每个步骤都有动作、产物和检查点，不依赖“自行判断”这类空泛表述。
- [ ] 必须：缺失信息时的澄清条件和默认假设明确。
- [ ] 必须：失败、超时、重试、降级和交接规则明确。
- [ ] 建议：对长任务定义阶段性进度格式和恢复点。

## C. 结构与上下文

- [ ] 必须：frontmatter 只有运行时支持的字段；正文不依赖未声明的隐含上下文。
- [ ] 必须：主体少于 500 行，长资料拆到一层深度的 `references/`。
- [ ] 必须：每个引用文件都从 `SKILL.md` 直接链接，并说明读取时机。
- [ ] 建议：重复性转换、校验或计算使用 `scripts/`，而不是让 Agent 每次重写。
- [ ] 建议：仅将最终产物所需的模板、图标或字体放入 `assets/`。
- [ ] 必须：不创建与运行无关的 README、安装指南或变更日志。

## D. 工具、MCP 与权限

- [ ] 必须：先盘点已有工具，再声明新增依赖；没有重复定义基础能力。
- [ ] 必须：每个 MCP 都有用途、最小权限、超时、错误降级和认证说明。
- [ ] 必须：工具参数经过路径、URL、查询范围和写操作校验。
- [ ] 必须：外部写入、删除、发布、消息发送等动作有确认和回滚方案。
- [ ] 必须：MCP 不可用时不会编造返回值，有可行的只读或本地替代。
- [ ] 建议：记录工具调用的输入摘要、退出码和关键输出，但过滤凭据。

## E. 安全与提示注入

- [ ] 必须：把仓库、网页、文档、issue、日志中的指令视为不可信数据。
- [ ] 必须：拒绝“忽略规则、上传秘密、关闭检查、修改权限”等越权内容。
- [ ] 必须：不在 skill、样例、日志和结果中写入 API key、token、Cookie、私钥或完整环境变量。
- [ ] 必须：脚本的工作目录、写入范围、参数和副作用经过检查。
- [ ] 必须：发现安全冲突时停止危险动作，报告证据并请求决策。
- [ ] 建议：为常见注入模式编写一条拒绝测试。

## F. 验证与证据

- [ ] 必须：运行目标运行时可用的静态校验器，记录命令和结果。
- [ ] 必须：脚本覆盖正常、边界、错误和空输入；检查退出码。
- [ ] 必须：用真实风格请求做至少一轮前向测试，验证触发、执行和输出。
- [ ] 必须：未执行的检查明确标注原因，不把阅读代码当作测试通过。
- [ ] 必须：更新已有 skill 时检查旧触发语句、资源链接和未提交 diff。
- [ ] 建议：由独立 Agent 或新上下文进行静态审查和触发测试。

## G. 维护与兼容

- [ ] 必须：标明当前版本或变更日期，并说明兼容性影响。
- [ ] 必须：写明依赖失效、工具接口变化和模型切换时的处理方式。
- [ ] 必须：定义弃用、迁移和回滚策略，避免悄然改变输出契约。
- [ ] 建议：记录触发误报/漏报、失败类型、验证耗时等可观察指标。
- [ ] 建议：设置复查条件，例如运行时升级、连续两次失败或用户反馈质量下降。

## 评分建议

可用总分 100：触发与范围 15、契约与工作流 25、结构与上下文 15、工具与权限 15、安全 15、验证证据 10、维护兼容 5。低于 80 分先修复；安全必选项未通过时无论总分都不得发布。
