# 模型路由、熔断与恢复

在任务风险升高、当前模型表现不稳定、调用超时或服务不可达时读取本文件。模型名称从 Hermes 当前 profile 和 provider 配置中发现，不假设某个固定模型永远可用。

## 能力路由

| 任务 | 优先能力 | 可降级条件 |
|---|---|---|
| 文件搜索、结构盘点、日志整理 | 工具调用稳定、成本低、上下文足够 | 输出由文件或命令复核 |
| 局部实现和测试 | 代码生成稳定、遵循差异、能运行工具 | 低风险且有强测试兜底 |
| 跨模块设计、复杂根因、迁移 | 最强可用编码与推理模型 | 不建议降级；必要时请求审查 |
| 安全、认证、并发、数据完整性 | 最强模型 + 独立审查 | 无可靠审查时不得静默发布 |
| 最终代码审查 | 与实现不同的强模型或独立 Agent | 无独立模型时切换上下文重新审查 |

不要用模型自述或品牌名称代替实测。以任务成功率、工具错误率、验证诚实度、差异质量和恢复能力选择模型。

## 触发升级

出现任一信号时从当前模型升级：

- 两次忽略明确仓库规则或验收条件；
- 两次引用不存在的文件、符号、命令或测试结果；
- 两轮根因假设均被证据推翻且没有形成更好的复现；
- 修改跨越三个以上模块或涉及公共接口、迁移、安全、并发；
- 无法解释最终差异与验收条件的对应关系；
- 连续工具失败后仍重复相同调用；
- 上下文压缩后无法恢复任务状态。

## 熔断状态

每个 provider 或模型维护以下逻辑状态：

- `CLOSED`：正常调用；
- `OPEN`：近期连续超时或连接失败，暂不调用；
- `HALF_OPEN`：冷却后用一个无副作用的小请求探测。

推荐默认阈值，可由运行环境覆盖：

- 单次响应超时：交互任务 90 秒，长工具任务按工具实际进度单独判断；
- 连续连接或超时失败：2 次后 `OPEN`；
- 冷却时间：60 秒；
- `HALF_OPEN` 探测：只执行短的只读请求；
- 同一任务最多切换模型：2 次，之后报告阻塞，避免无限循环。

只有连接错误、明确超时、服务端不可用或无响应触发连通性熔断。代码测试失败、模型给出错误答案或用户拒绝方案不属于网络熔断，应走调试或重新规划。

## 切换步骤

1. 停止等待当前调用，记录失败类型、时间和重试次数。
2. 确认是否有外部副作用或未完成写入；状态未知时先只读核对。
3. 保存 checkpoint，至少包含目标、当前阶段、已改文件、实际验证、未完成动作和风险。
4. 从当前 profile 的可用 fallback 中选择已通过连通性探测且能力足够的模型。
5. 向新模型提供用户原始目标、适用规则、checkpoint、当前 diff 和关键工具输出。
6. 要求新模型先复核状态，再继续下一未完成动作。
7. 切换后重新运行最窄验证；不能沿用旧模型未经工具证明的结论。

## 防止重复副作用

以下操作切换后不得直接重放：

- 发布、推送、部署和发送消息；
- 数据库写入或迁移；
- 删除、覆盖、移动大量文件；
- 创建远端资源、支付或触发外部工作流。

先检查操作是否已经完成、是否部分成功、是否支持幂等键或回滚。无法确定时停止并让用户决策。

## Checkpoint 交接示例

```text
目标：修复导入接口在空 CSV 时返回 500 的问题。
阶段：实现后定向验证。
事实：异常来自 parser.py 的 rows[0]；旧测试未覆盖空文件。
已修改：tests/test_import.py、src/parser.py。
验证：空文件回归测试通过；模块测试尚未运行。
下一步：运行 importer 模块测试，再检查最终 diff。
副作用：无外部写操作。
失败：模型 A 连续两次 90 秒超时，熔断已打开。
```

交接摘要只包含可复查事实和必要决策，不包含完整内部推理或秘密。

## 当前 Hermes 配置的使用原则

Hermes 桌面端、命令行和不同 profile 可能读取不同配置源。执行前显示当前 profile、默认模型和 fallback 的非敏感名称；若与用户所述不一致，以实际启动会话所显示的 profile 为准，并报告差异。不要在 skill 内保存 API key、base URL 中的敏感查询参数或认证头。
